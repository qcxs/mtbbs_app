# 帖子缓存与离线帖子

> 适用：维护/扩展帖子自动缓存、离线副本、缓存管理页、导入导出或损坏恢复时。**改动前先读第 4 节（v1 冻结约束）与第 8 节（损坏处理）**。用户侧导出格式见 `docs/25-帖子缓存导出格式与自解析指南.md`。

## 1. 目标与边界

新帖可能因删帖、审核、作者改成「已删除」而消失。本功能在**不改变网络优先浏览**的前提下，为帖子保存内容级快照：

- **自动缓存**：新帖每次成功加载后异步写入，只记录用户实际看过的内容，有 TTL，不提供「永不过期」。
- **离线副本**：用户主动保存，永不过期，一帖一份。
- **读取**：正常浏览**完全不读缓存**；只有用户点「查看缓存」或加载失败时才进入只读快照页。
- 缓存**不加密**（需求明确，便于用户自行解析），隐私风险见 `docs/25` 第 10 节。

## 2. 数据分类

| 类型 | 触发 | 过期 | 评论区 | 删除 |
|---|---|---|---|---|
| 自动缓存 | 新帖成功访问 | 默认 1 天，可选 1/3/7/14/30 天 | 只保存已加载页，不额外抓取 | 按帖删除 / 过期清理 / 清空 |
| 离线副本 | 用户手动保存 | 永不 | 保存前询问是否加载全部 | 按帖删除 / 清空 |
| 帖子预览缓存 | 引用预览（`post_preview.dart`） | FIFO 100 条 | 不适用 | 与本功能无关 |

自动与离线互不影响：清空自动缓存不删除离线；删除离线也不影响自动缓存。

## 4. 独立数据库与 Schema v1 冻结

缓存使用独立 `{appDataDir}/threads.sembast`，**刻意不经过 `DatabaseHelper`**：
缓存正文体积远大于设置/历史，放主库会放大损坏与变慢的影响面；独立文件损坏、清空、重建都不触碰主库、登录态与设置。这是对「持久化统一走 `DatabaseHelper`」的**有意例外**，不是遗漏。

| Store | Key | 内容 |
|---|---|---|
| `meta` | `schema` | `{version: 1, createdAt}` |
| `thread_meta` | 见下 | 轻量索引（列表、统计、过期清理、版本裁剪） |
| `thread_data` | 与索引同键 | 完整快照 JSON |

键格式：自动 `auto|{host}|{viewer}|{tid}|{contentHash}`；离线 `offline|{host}|{tid}`。`viewer` 为 `uid:<uid>` 或 `guest`（`ThreadCacheService.viewerTag` 幂等归一）。**键必须含 host**：不同站点 `tid` 独立编号。

**v1 冻结（硬约束）**：

1. 不做字段重命名、类型变更、必填性变更、嵌套层级调整。
2. 只允许**追加可选字段**；旧数据与第三方解析器忽略未知字段即可正常工作。
3. `schemaVersion` 保持 `1`；只有破坏性变更才提升版本，且必须提供显式迁移/导出方案。
4. 导出顶层 `format=mtbbs.thread_cache`、`schemaVersion`、`items` 结构同样冻结。
5. 不加密是长期约定，不引入密钥或平台安全存储。
6. 不做多版本迁移框架；高于支持版本的导入整份拒绝。

`ThreadSnapshotMeta` 是内部索引（非导出格式），序列化时带 `key` 字段以便列表直接读取；正文快照由 `thread_data` 的 JSON 还原，读取时用 `PostItem.fromMap`，**不重新解析 HTML**。

## 5. 自动缓存

**写入条件**：`_loadInitial` 第 1 页成功且拿到楼主帖、非作者筛选视图（`authorid == null`）、`postTime` 判为新帖、缓存未禁用、且用户未关闭总开关（`SettingsProvider.threadCacheEnabled`，默认开启）。写入通过 `unawaited(onThreadLoaded(...))` 异步执行，不阻塞渲染；失败只记 `AppLogger.w('THREAD_CACHE', ...)`。

**总开关**：缓存管理页「自动缓存」Tab 顶部的「自动缓存新帖」开关（持久化键 `threadCacheEnabled`，默认 `true`）。关闭只停止**后续写入**，已有缓存照常可查看、导出与清理；离线副本不受影响。

**新帖判定**（`isNewThreadTime`，只认楼主帖 `postTime`，不用列表时间，采用**排除法**）：空串 → 非新帖；文本任意位置含 `刚刚|刚才|今天|昨天|前天|秒前|分钟前|小时前|天前` → 新帖（兼容「发表在 半小时前」「昨天 12:34」这类输出）；含完整时间（`2026-10-30 13:04`、`2026/10/30 13:04`、`2026年10月30日 13:04`、无年份的 `10-30 13:04`）→ 由 `parsePostTime` 解析后与当前时间比较，距今不超过 `kNewThreadWindow`（7 天）才算新帖，未来时间（站点时钟偏差）也按新帖；日期非法或完全无法识别 → 按新帖处理——宁可多缓存，也不因模板措辞差异漏掉自动缓存。52pojie 等站点所有帖子都显示完整时间，此前会被一律判成旧帖而从不缓存，该窗口解决了这一点。

**内容版本**：`contentHash = fnv1a64(utf8(normalize(title) + "\0" + normalize(bbcode)))`，只统一换行与首尾 trim，**不折叠内部空白**（避免 `[code]` 缩进差异被误判）。不包含 `postTime`/`ipLocation`/评分等易变字段。每帖最多 **3 个内容版本**：内容不变只更新评论与时间；内容改回旧版命中已有版本，不新增第 4 版。

**评论页**：初次写入保存第 1 页；用户后续成功加载第 N 页时经 `onCommentPageLoaded` 回写该页；**绝不主动抓取未加载页**，`totalPages` 只用于显示「已缓存 X/Y 页」。请求失败不回写、不删旧页。

**TTL**：`SettingsProvider.threadCacheDays`（下限 1），默认来自 `assets/config/cache.json` 的 `thread.expireDays`。每次成功访问刷新该帖全部保留版本的 `expiresAt`（只改索引，不重写正文）。过期清理与图片缓存一致：**App 启动时清一次**（`main` 里 `unawaited` 调用，不阻塞首屏），缓存管理页刷新与手动「清理过期」时再跑；只删 `auto` 且已过期的记录。

**单帖上限**：`thread.maxBytesPerThread`，默认 4 MiB。自动缓存按该帖所有版本合计：新快照本身超限 → 跳过；加入后超限 → 先淘汰最旧版本，仍超限则跳过。**自动缓存超限静默**（只记 WARN）。

**不缓存**：非新帖、作者筛选、楼主帖为空/解析降级、加载失败、缓存禁用/损坏、超限。

## 6. 离线副本

入口为帖子页菜单「保存离线副本」；作者筛选视图拒绝保存。同 `(host, tid)` 已存在时先弹覆盖确认。

保存前若存在未加载评论页，询问三选一：**加载全部评论并保存** / **仅保存已加载** / 取消。加载全部复用页面现有 `_loadCommentPage`（`switchPage: false`，不跳页），逐页显示进度；中途失败或取消时询问是否保存已获取的部分。

离线快照 `viewer=null`、`expiresAt=null`，另存 `savedBy`（仅展示，不做鉴权）。超限返回 `ThreadCacheSaveStatus.tooLarge` 并提示实际大小；若因「加载全部」导致超限，提供回退「仅主帖 + 第 1 页」。**一帖一份**，覆盖即整体替换。

## 7. 读取与只读页

- 正常成功路径不显示缓存横幅、不做 stale-while-revalidate。
- 加载失败时异步查 `thread_meta`；有缓存才在错误页显示「查看缓存」，缓存禁用时改为提示文字；**不自动跳转**。
- 快照选择器：1 份直接打开；多份底部弹层按时间倒序，离线置顶并标注。
- 只读页不是独立页面：`ThreadViewPage(cacheKey:)` 复用同一套宽/窄屏布局、滚动与分页状态，只是数据来自快照；内部复用 `MainPostSection` / `CommentSection` / `ThreadPostCard`，通过 `readOnly: true` 隐藏回复、评分、编辑、更多菜单（测试见 `test/thread_post_card_readonly_test.dart`）。
- 分页只允许切到 `cachedPages`；未缓存页显示「该页未缓存」；顶部只读横幅直接提供「切换版本」按钮（同帖其他快照，`pushReplacement` 原地替换），AppBar 菜单同时保留该入口与「重新加载最新」（跳回网络页）。
- 图片仍是原始 URL，走现有 `CachedNetworkImage`；文本缓存不保存图片二进制，缓存过期后可能加载失败，这是既定边界。

## 8. 损坏与禁用

| 级别 | 触发 | 行为 |
|---|---|---|
| 文件级 | DB 打不开、事务失败、文件格式损坏 | 健康状态置 `corrupted`，整体禁用；`ValueNotifier<ThreadCacheHealth>` 通知 UI |
| 单条 | 某条 JSON 解码/索引解析失败 | 跳过该条并记 WARN，不影响其他记录，也不禁用 |

文件级损坏后：App 壳层 `app_shell.dart` 监听健康状态，**每会话只 Toast 一次**（「帖子缓存文件损坏，缓存功能已禁用；请在缓存管理中导出备份或重建。」）；自动写入直接跳过，手动查看提示「缓存不可用」，离线保存提示已禁用。**不自动删除、不自动重建、不自动重试**，重启后仍保持禁用。

管理页损坏横幅提供四个动作：**导出原始文件**（复制 `.sembast` 及伴随文件）、**尽力导出 JSON**（跳过坏记录）、**重建**（原文件改名 `.corrupt-{timestamp}` 保留备份；改名失败需用户确认后才删除）、**清空并重建**（明确提示离线副本会丢失）。只有重建/清空成功才解除禁用；仅导出不解除。

## 9. 配置与设置

- `assets/config/cache.json` → `thread: { expireDays, maxBytesPerThread }`；读取见 `DefaultConfig.threadCacheConfig`，非法值回退 1 天 / 4 MiB。
- 设置持久化：`SettingsProvider.threadCacheDays`（`setSettingInt('threadCacheDays')`，clamp 1~365），加载时同时 `ThreadCacheService.configure(...)`。
- 管理页只展示单帖上限，不提供用户可调；UI 过期选项固定 1/3/7/14/30 天，**没有「永不过期」**。

## 10. 导入导出

- 导出跟随当前 Tab：自动 Tab 导出当前账号的自动缓存，离线 Tab 导出全部离线副本；UTF-8 pretty-print 明文 JSON。
- 文件名 `mtbbs_threads_{yyyyMMdd_HHmmss}.json`；顶层与字段语义以 `docs/25` 为准，改动前先核对冻结约束。
- 「另存为」不可用（如部分鸿蒙版本）时写入 `{appDataDir}/exports/` 并提示路径；能力缺失由 `AppCapabilities.filePicker` 降级。
- 导入前预览统计（可导入/冲突/超限/损坏）；自动缓存 `viewer` 改写为当前账号、`lastVisitedAt=now`、`expiresAt=now+TTL`；离线冲突询问「覆盖全部 / 跳过全部」；单条损坏只跳过。
- 原始 `.sembast` 只支持导出备份，不提供导入（避免覆盖运行中的数据库）。

```bash
flutter analyze lib
flutter test test/thread_cache_test.dart test/thread_post_card_readonly_test.dart
```

手工闭环：打开新帖 → 管理页出现条目；评论翻页后版本数不变、评论页更新；删帖后错误页「查看缓存」可读；离线保存两种评论策略；导出/导入往返；人为破坏 `threads.sembast` 后 Toast/禁用/重建恢复。

本功能不新增网络 API，不需要 `tool/api_probe_test.dart`。
