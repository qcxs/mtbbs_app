# 版本管理与发布

> 适用：发布新版本（本地手动打包 / GitHub Actions 自动发布）。参考成熟项目 PiliPlus 的方案落地。

## 版本号规则

| 组成 | 来源 | 示例 |
|------|------|------|
| 版本名（versionName） | **pubspec.yaml 的 `version:` 行**（唯一事实源，发布前手动改） | `1.1.0` |
| 构建号（versionCode） | `git rev-list --count HEAD`（提交总数，单调递增） | `35` |
| commit hash | `git rev-parse HEAD`，Android 发布包版本名追加前 9 位 | `1.1.0-abcdef123` |

- 运行时元数据由 `lib/config/build_config.dart` 提供（dart-define 注入，默认值 SNAPSHOT/0/N/A），设置页「关于」已显示实际版本。
- **发布前只改一处**：`pubspec.yaml` 的 `version:`，其余全部自动派生。
- **tag ≠ 应用版本名**：GitHub Release 的 tag（如 `v1.0.0-pro`）只用于命名 Release，**不会进入应用**；应用内显示的版本名一律来自 pubspec `version:` 行。发布预发布版（如 pro/beta/rc）时，请把 pubspec 改成带后缀的 semver（如 `version: 1.0.0-pro+1`），脚本会自动保留 `-pro` 后缀（`+build` 段丢弃，构建号仍取 git 提交数）。

## 发布流程（通用）

1. 改 `pubspec.yaml` 的 `version: x.y.z+n`（n 可随意，实际以 git 提交数为准）
2. 提交并推送代码
3. 按下面「GitHub 发布」或「本地发布」执行

---

## GitHub 发布（推荐）

### 首次配置

1. 在 GitHub 仓库 **Settings → Secrets and variables → Actions** 添加（全部可选，不配则用 debug 签名）：
   - `SIGN_KEYSTORE_BASE64` — 签名 keystore 的 Base64 编码（`certutil -encode` 后去掉头尾行）
   - `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`
2. 若无签名文件，可本地生成：

```powershell
keytool -genkey -v -keystore android\app\key.jks -alias mtbbs -keyalg RSA -keysize 2048 -validity 10000
# 然后 base64 编码后填入 SIGN_KEYSTORE_BASE64
certutil -encode android\app\key.jks key.b64
```

### 发布步骤

1. 仓库页面 → **Actions → Release** → **Run workflow**
2. 参数：
   - `build_android` / `build_windows` — 勾选要构建的平台
   - `tag` — **填写 Release tag（如 `v1.0.0`）** → 构建完成后自动发布到该 tag 对应的 GitHub Release 页；**留空** → 仅构建并作为 workflow artifact 保留（Actions 页面下载）
3. 等待构建完成，在 Releases 页面得到：

| 平台 | 产物 |
|------|------|
| Android | `MTBBS_android_{版本}_{abi}.apk`（arm64-v8a / armeabi-v7a / x86_64 三个） |
| Windows | `MTBBS_windows_{版本}_x64_setup.exe`（安装包）+ `..._portable.zip`（便携版） |

> tag 需预先存在或由 workflow 自动创建均可：`softprops/action-gh-release` 在 tag 不存在时会自动创建。建议先手动 `git tag v1.0.0 && git push --tags` 再触发，Release 页描述可在发布后编辑补充。

## 本地发布

### Windows（安装包 + 便携版）

前置：Visual Studio **2022**（17.13+，推荐 17.14，勾选「使用 C++ 的桌面开发」）、Windows 10/11 SDK（**10.0.22621** 或更新，装 VS2022 时一并勾选）、[Inno Setup](https://jrsoftware.org/isinfo.php) 6+（iscc 在 PATH 中）。工具链版本对齐原则见下方「工具链对齐」小节，**不要**无脑用最新版。

```powershell
# 1. 生成版本信息（读 pubspec + git，写 mtbbs_release.json，导出环境变量）
powershell -ExecutionPolicy Bypass -File scripts\version.ps1

# 2. 编译 release（版本号通过 --build-name/--build-number 注入）
flutter build windows --release `
  --dart-define-from-file=mtbbs_release.json `
  --build-name=$env:MTBBS_VERSION_NAME `
  --build-number=$env:MTBBS_VERSION_CODE

# 3. 生成安装包（版本号自动取 MTBBS_VERSION_NAME 环境变量）
iscc installer\setup.iss
#   输出：build\MTBBS_v{版本}_Setup.exe

# 4. （可选）便携版 zip
Compress-Archive -Path build\windows\x64\runner\Release\* -DestinationPath "build\MTBBS_windows_$env:MTBBS_VERSION_x64_portable.zip"
```

注意：编译前结束 mtbbs.exe 进程，避免文件锁定：

```powershell
Get-Process mtbbs -ErrorAction SilentlyContinue | Stop-Process -Force
```

### Android（APK）

```powershell
# 1. 生成版本信息（android 参数会在版本名后追加 commit hash）
powershell -ExecutionPolicy Bypass -File scripts\version.ps1 android

# 2. 构建（默认 arm64，其他 ABI 加 --target-platform）
flutter build apk --release `
  --dart-define-from-file=mtbbs_release.json `
  --build-name=$env:MTBBS_VERSION_NAME `
  --build-number=$env:MTBBS_VERSION_CODE `
  --target-platform android-arm64

# 输出：build\app\outputs\flutter-apk\app-release.apk
```

本地签名：在 `android/` 下放置 `key.properties`（`storeFile`/`storePassword`/`keyAlias`/`keyPassword`）即可用正式签名，否则回退 debug 签名（仅用于自测）。

### Android beta（预发布测试，与正式版共存）

正式版装到手机上后，Android **不允许降级安装**（versionCode 更低的包装不上去）。beta 独立 `applicationId`（`com.github.qcxs.discuz.beta`）+ 独立应用名（「MT论坛 beta」），与正式版是**两个互不干扰的应用**，versionCode 高低互不影响，装/卸都随便，随时可卸载 beta 装回正式版。

```powershell
# 1. 生成版本信息
powershell -ExecutionPolicy Bypass -File scripts\version.ps1

# 2. 构建 beta（直接调 gradle；flutter CLI 不支持自定义 buildType）
Set-Location android
$v = Get-Content ..\mtbbs_release.json | ConvertFrom-Json
.\gradlew.bat assembleBeta "-Pflutter.versionName=$($v.'mtbbs.name')" "-Pflutter.versionCode=$($v.'mtbbs.code')"
# 输出：android\app\build\outputs\apk\beta\app-beta.apk（调试包 adb install 即可）
```

说明：
- 签名与 release 同逻辑（有 `key.properties` 用正式签名，否则 debug 签名）；beta 是独立应用，签名与正式版是否一致都无所谓。
- 未注入 dart-define 时「关于」页显示 SNAPSHOT，beta 自测可接受；需要完整版本信息可先 `flutter build apk --release` 生成后的 `mtbbs_release.json` 内容自行用 `--dart-define` 补齐（非必需）。
- 卸载 beta 不影响正式版数据（独立数据目录）。

### 手动发布到 GitHub

本地构建产物可手动创建 Release：GitHub 仓库 → **Releases → Draft a new release** → 填 tag（`v1.0.0`）→ 拖入 APK / exe / zip → 发布。

## 工具链对齐（VS2022，勿用最新）

Windows 构建环境以**当前依赖的支持基线**为准，不盲目追最新：

| 组件 | 对齐版本 | 依据 |
|------|---------|------|
| Visual Studio | **2022**（17.13/17.14，MSVC 14.4x） | `flutter_inappwebview` 6.x 是本项目 Windows 端唯一重度 C++ 插件，其官方支持/测试基线是 **VS2022**；对 VS2026 的适配 PR（WebView2/WIL 升级）尚未合入 |
| MSVC | 14.4x | STL1011（`<experimental/coroutine>` 硬错误）只在 **14.5x（VS2026）** 触发；14.4x 只是警告或不触发 |
| Windows SDK | **10.0.22621**（或更新） | GitHub windows-2022 镜像自带版本，与 CI 一致 |
| GitHub CI runner | `windows-2022` | 镜像 = VS2022 17.14 + SDK 22621 + 预装 Inno Setup 6.7.1 |

- 本地**不要用 VS2026 编译本项目 Windows 端**：其 MSVC 14.5x 对 `<experimental/coroutine>` 触发 STL1011 硬错误，且 `flutter_inappwebview` 6.x 尚未适配 VS2026。工具链对齐到 VS2022 即可（本项目的 `windows/CMakeLists.txt` 无任何环境兼容宏，即该基线下的原生写法）。
- 若以后 `flutter_inappwebview` 升级到官方已适配 VS2026 的版本，再评估 CI 切回 `windows-latest`。

## 常见问题

- **关于页显示 `vSNAPSHOT+0`**：说明是直接 `flutter run` / 未走 version.ps1 的构建，属正常。
- **Android 版本名带 hash**：`1.1.0-abcdef123` 便于用户反馈时定位提交，正式商店上架可去掉（改 version.ps1 第 4 步）。
- **安装包版本号不对**：确认 `scripts\version.ps1` 与 `iscc` 在**同一个** PowerShell 会话/步骤中执行（环境变量不跨会话持久）。
- **`key.properties` 首行 BOM 陷阱**：Java `Properties.load` 不识别 UTF-8 BOM，会把首键读成 `\uFEFFstoreFile` 导致 `storeFile` 判空、静默降级 debug 签名。已双保险：gradle 侧读取时剥 BOM；CI 写入用 `.NET` 无 BOM 编码。**手动创建 `key.properties` 时注意别带 BOM**（VS Code 右下角可切换编码，选 UTF-8 不带 BOM 或 ANSI）。
- **Windows 构建 STL1011（C++/WinRT coroutine）**：`flutter_inappwebview_windows` 依赖的 C++/WinRT 在 C++17 下会 include `<experimental/coroutine>`，新版 MSVC STL（**VS2026 / 14.5+**）会 `static_assert` 报 `error STL1011`（14.4x 无此错误，已验证本机 14.44 头文件无该断言）。项目已对齐 **VS2022（MSVC 14.4x）**，`windows/CMakeLists.txt` 无需也不含兼容宏；**若误用 VS2026 编译仍会触发**，等 `flutter_inappwebview` 官方适配 VS2026（PR 含 WebView2/WIL 升级）后再评估升级。注意**不要**用 C++20 规避：`<experimental/coroutine>` 头在 C++20 标准协程开启时有 `#error` 守卫。
- **iscc 报找不到 `ChineseSimplified.isl`**：该文件是 Inno Setup 的**非官方翻译**，官方安装包/choco 包都不附带（本地之前能过是因为 Languages 目录里恰好有）。已对齐 PiliPlus 方案：**随仓库内置**（`installer/ChineseSimplified.isl`），CI 打包前 `Copy-Item` 到 Inno Setup 的 Languages 目录。注意**不能用 `Get-Command iscc` 定位目录**——choco 的 iscc 是 Chocolatey shim，取到的是 `chocolatey\bin` 转发壳而非真实安装目录，必须硬编码 `C:\Program Files (x86)\Inno Setup 6\Languages`。**本地全新安装 Inno Setup 后**若遇此错，把仓库里的 `installer/ChineseSimplified.isl` 拷到 `C:\Program Files (x86)\Inno Setup 6\Languages\` 即可。
- **上游插件编译警告（统一抑制）**：`flutter_inappwebview_windows` 插件及 WebView2 依赖的警告为上游已知问题，已在本项目 `windows/CMakeLists.txt` 定向抑制：`CMAKE_SUPPRESS_DEVELOPER_WARNINGS`（全局关闭 CMake dev 级警告）+ 插件目标的 `/wd4819 /wd4244 /wd4458`（**本项目代码仍保持 `/W4 /WX` 严格编译**）。等插件官方适配 VS2026 的 PR（WebView2/WIL 升级）合入后可再评估移除。
