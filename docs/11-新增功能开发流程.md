# 11-新增功能开发流程（AI 冷启动手册）

> 面向**无项目上下文**的 AI：从零新增一个"列表/详情"类功能（如好友列表）的完整操作手册。
> 本文档由"好友列表"功能实战提炼（2026-08-01），按阶段执行即可复现同样效果。
> 核心原则：**每一步都要有真实证据**（Chrome 看 DOM、探针跑真实请求、analyze 通过），不要凭猜测写代码。

## 0. 环境认知（先读这些，建立上下文）

| 文件 | 作用 |
|---|---|
| `lib/api/**/{http,parse,export}.dart` | API 三层结构：http=请求、parse=HTML→Map、export=汇总入口（parseWithLog） |
| `lib/api/helpers.dart` | `parseWithLog(resp, parseFn)`：统一记录日志并自动截断大列表（前 3 项） |
| `lib/core/app/page_helper.dart` | `extractPagination(doc)`（.pg 分页栏）、`checkPageError(doc, body)`（Discuz 错误页/登录页检测）、`sanitizeText` |
| `lib/services/api_service.dart` | `ApiService().dio` 统一 Dio（已带 UA/Cookie），`switchToAccount/switchToGuest` |
| `lib/core/utils/url_router.dart` | Discuz URL → App 路由映射（内置浏览器"用 App 打开"依赖它） |
| `lib/config/router.dart` | GoRouter 路由表（`/friends?uid=` 这类带参路由的写法） |
| `tool/api_probe_test.dart` + `tool/api_scenarios.dart` | 探针：真实请求 API 并输出 JSON（见 `docs/10-API探针使用规范.md`） |
| `lib/core/app/app_paths.dart` | Cookie 目录（`%APPDATA%\qcxs\mtbbs_debug\cookies\{host}`），探针/App 共享 |
| 组件库 | `widgets/common/user_avatar.dart`（UserAvatar）、`widgets/layout/state_views.dart`（LoadingView/EmptyView）、`widgets/layout/page_error_widget.dart`、`widgets/layout/pagination_bar.dart` |

**项目铁律**：日志用 `AppLogger`（禁 print）；import 用 `package:mtbbs/...` 绝对路径。

## 1. 阶段一：DOM 分析（MCP Chrome）

1. 让用户打开目标页面（或你打开），用 `list_pages` 确认页面已打开。
2. 用 `evaluate_script` 提取结构（**输出要克制，避免爆上下文**）：
   ```js
   // 首次：找容器/列表/分页的大结构
   const bm = document.querySelector('.bm_c');
   ({hasBmC: !!bm, bmClass: bm?.className,
     lis: bm?.querySelectorAll('ul li').length,
     firstLi: bm?.querySelector('ul li')?.outerHTML.slice(0, 1500),
     pagination: document.querySelector('.pg')?.innerText})
   // 第二次：针对具体项提取完整 HTML（列表项/卡片内部结构）
   document.querySelector('ul.buddy.cl > li')?.outerHTML
   ```
3. **必须看真实渲染 DOM**（不能脑补）。本次实战教训：静态分析完全预判不到"自己页 vs 他人页"的 DOM 差异，只有连上实际页面才暴露。
4. 提取完把 DOM 结构写进 parse.dart 的 doc 注释（方便后续维护）。

## 2. 阶段二：API 层编写（http / parse / export）

`lib/api/<模块>/` 下新建三个文件（模块按 Discuz 页面归类，如好友=home/friend）：

**http.dart** — 只有请求，无逻辑：
```dart
Future<Response<String>> getFriendList(Dio dio, {String uid = '', int page = 1}) {
  // uid 空 = 当前登录用户；Dio 的 baseUrl/UA 由 ApiService 统一提供
  return dio.get<String>('/home.php?mod=space&uid=$uid&do=friend&from=space&page=$page');
}
```

**parse.dart** — 返回 `Map<String, dynamic>`，遵循统一骨架：
```dart
Map<String, dynamic> parseResponse(String body, int statusCode) {
  if (statusCode != 200) return {'success': false, 'message': 'HTTP $statusCode'};
  final doc = html_parser.parse(body);
  final pageError = checkPageError(doc, body);          // Discuz 错误页/登录检测（统一）
  if (pageError.isError) return {...};
  // ① 特殊业务态检测（如权限受限 .nfl h2 → privacyBlocked）
  // ② 主列表解析（querySelectorAll 循环，每个 item 一个函数 _parseXxx）
  // ③ 分页：extractPagination(doc) → currentPage/totalPages/hasMore
  // ④ 日志 AppLogger.i('PARSE', '...'); 返回
}
```

**export.dart** — 汇总入口：
```dart
Future<Map<String, dynamic>> getFriendList(Dio dio, {String uid = '', int page = 1}) async {
  final resp = await http.getFriendList(dio, uid: uid, page: page);
  return parseWithLog(resp, parse.parseResponse);
}
```

**关键决策点**：
- **登录需求**：页面是否可游客访问？不确定就先按"可游客"测，探针实测发现跳登录再改 `needsLogin: true`。
- **DOM 变体**：同一页面在"自己/他人/未登录"下结构可能不同（Discuz 常见），每个变体都要真实打开看。
- **UA**：默认走 ApiService；个别接口（导读/版块/我的帖子）用 `Options(headers: {'User-Agent': site.userAgent})` 覆盖（移动/桌面切换能力）。
- **表单/Post**：Dio 对 Map 数据**不自动加 Content-Type**，Discuz 依赖 `$_POST` 时必须显式 `Options(headers: {'Content-Type': Headers.formUrlEncodedContentType})`（编辑器提交曾因此报"表单验证串不符"）。

## 3. 阶段三：探针验证（真实请求，必须先于页面开发）

在 `tool/api_scenarios.dart` 注册场景：
```dart
'friend.list': ApiScenario(
  desc: '好友列表（uid 空=自己的好友，指定 uid=查看该用户）',
  params: {'uid': '用户 ID（可空=自己）', 'page': '页码（默认 1）'},
  run: (a) => friend_api.getFriendList(ApiService().dio, uid: ..., page: ...),
),
```
运行（参考 `docs/10-API探针使用规范.md`）：
```bash
flutter test tool/api_probe_test.dart --dart-define=cmd=friend.list --dart-define=uid=14330 --dart-define=log=off
```

**验证矩阵（按情况选）**：
| 场景 | 命令 | 检查点 |
|---|---|---|
| 游客 | `uid=<公开用户>` | 列表字段完整 |
| 登录态 | `account=账号名`（先 `session.list` 看账号） | 自己的数据 |
| 隐私受限 | `uid=<设隐私的用户>` | `privacyBlocked: true` |
| 多站点 | `site=1 account=账号` | 换站换 Cookie |
| 大数据量 | 好友多的 uid 会超时 | 用小数据量 uid；大结果自动截断前 3 项 |

**坑**：
- 新参数键必须加进 `api_probe_test.dart` 的 `args` map（逐键显式 `const String.fromEnvironment`，循环变量失效）。
- 测试数据选**代表性小数据**（uid=1 有 2227 好友会超时，换 uid=14330）。

## 4. 阶段四：页面开发（复用组件，不造轮子）

`lib/pages/<模块>/<name>_page.dart`。好友页 = 账号头部 + 搜索框 + 自适应网格 + 底部翻页。

**直接抄已有页面**：
- 自适应网格：`lib/pages/online/online_page.dart` 的 `LayoutBuilder` + `crossAxisCount = (maxWidth/160).floor().clamp(1,8)` + GridView（宽屏多列）
- 翻页：`PaginationBar(page:, totalPages:, onGoToPage:)` 放底部
- 搜索框 + 空结果提示：online_page 的 `_searchController/_filteredItems` + EmptyView（搜索无结果用 `Icons.search_off` + "未找到匹配结果"）
- 错误态：`PageErrorWidget(message:, onRetry:)`；**隐私/权限受限时 `onRetry: null`**（重试无意义）
- 头像：`UserAvatar(uid:, nickname:, radius:)`（自动走 CDN/缓存/错峰）
- 空态/加载态：`EmptyView`/`LoadingView`

**页面消费键名核对（重要）**：探针验证的是 API 层返回，**不等于页面字段正确**。
探针输出里 `profile.nickname`、`profile.activity.userGroup`（不是 `username`/顶层 `userGroup`）。
每个被页面读取的键都要对着探针 JSON 核实一遍。

## 5. 阶段五：路由 + 入口 + URL 映射

1. **GoRoute**（`lib/config/router.dart`）：带参路由用 `state.uri.queryParameters` 读参数：
   ```dart
   GoRoute(path: '/friends', pageBuilder: (_, state) {
     final uid = state.uri.queryParameters['uid'];
     final page = int.tryParse(state.uri.queryParameters['page'] ?? '') ?? 1;
     return NoTransitionPage(child: FriendPage(uid: uid, initialPage: page));
   }),
   ```
2. **页面入口**：`my_profile_page.dart` 加 `ListTile` → `context.push('/friends')`；个人空间页统计卡（回帖/主题有跳转，好友也要补）→ `context.push('/friends?uid=$uid')`。
3. **UrlRouter 映射**（`lib/core/utils/url_router.dart`）——让内置浏览器里点 Discuz 链接能跳 App 内：
   ```dart
   // home.php?mod=space 分支内，uid 处理之前：
   if (query['do'] == 'friend') {
     final hasUid = uid != null && uid.isNotEmpty;
     final page = _resolvePage(query['page']);
     final params = <String, String>{ if (hasUid) 'uid': uid!, if (page > 1) 'page': '$page' };
     final qs = params.isEmpty ? '' : '?${params.entries.map((e) => '${e.key}=${e.value}').join('&')}';
     return UrlRouteResult(label: hasUid ? '好友列表' : '我的好友', appPath: '/friends$qs', ...);
   }
   ```
   **坑**：query 拼接**第一个参数必须用 `?`**（曾写出 `/friends&page=2` 导致 GoException: no routes）。构造 query 用 Map 统一拼，别手动拼 `&`。

## 6. 阶段六：回归验证

1. `flutter analyze`（无 issue）
2. 探针多场景回归（第 3 节的矩阵，至少覆盖：正常页 + 隐私页 + 自己页 + 大数据量）
3. URL 路由映射：写**临时测试** `tool/xxx_check_test.dart` 覆盖 URL→appPath 各组合（含边界：空 uid=、page>1 无 uid），跑完**删除**：
   ```dart
   SiteStore.instance.init();
   expect(UrlRouter.parse(url).appPath, expected, reason: url);
   ```
4. 临时测试不要留垃圾文件（跑完 DeleteFile）。

## 8. 实战复盘：好友列表（本次方法论来源）

| 遇到的问题 | 教训 |
|---|---|
| uid=1 有 2227 好友，响应超时 | 测试数据选代表性小数据（uid=14330，524 页 300ms） |
| 自己页 h4 首个 `<a>` 是"热度"链接（href=spacecp） | 选择器必须过滤 `space-uid-` 链接，不能 `h4 a` 直接取 |
| 自己页 `p.maxh` 是好友备注，他人页是"用户组 积分数: N" | 按"积分数:"格式区分 → userGroup+credits / note |
| 隐私页（康哥 uid=100）无 `.buddy` 列表，`.nfl h2` 提示 | 检测 `.nfl h2` → `privacyBlocked: true`，页面隐藏重试 |
| `user.info` 键是 `nickname`/`activity.userGroup` | 页面消费键名必须对探针 JSON 核实 |
| `/friends&page=2` → GoException | query 第一个参数用 `?`，用 Map 统一拼接 |
| 探针三元表达式 `'' : a['uid']` 类型不一致 | Dart 三元两分支类型须一致（`a['uid'] ?? ''`） |
