# 状态管理与站点配置

> 适用：状态管理（ChangeNotifier/Provider）、站点切换顺序、持久化方案。按需。

## 状态管理

`ChangeNotifier + Provider`。`notifyListeners()` 统一由持久化基座方法调用。

关键 Provider：`SettingsProvider`（全局设置）、`AuthProvider`（登录态）、`HistoryProvider`（浏览记录）。

## 站点切换

严格顺序不可颠倒：

1. `saveCurrentSiteState()` — 持久化当前站点的状态（如编辑中的 formhash）
2. `SiteConfig.switchTo(index)` — 更新 `SiteConfig.current` 和 `ApiService` 的 baseUrl
3. 各 Provider 重新 `load()` 对应站点的数据

### 跨站点会话（不切站点也能读别的站）

全局仍只有"当前站点 + 当前账号"，但身份可按页面传入：路由 location 带
`site=<host>`（可选 `as=<账号>`）时，`SiteScope` 给该页注入"该站默认账号/游客"的
临时只读会话，页面用 `SiteScope.of(context).dio` 而不是 `ApiService().dio`。
详见 `docs/27-跨站点会话与多用户.md`。

## 持久化

- 全应用统一用 **sembast**（`DatabaseHelper`，`{appDataDir}/mtbbs.sembast`），替代 SharedPreferences
- **例外**：帖子缓存使用独立库 `{appDataDir}/threads.sembast`（`ThreadCacheDatabase`），刻意不走主库以隔离大体积正文与损坏风险，见 `docs/24-帖子缓存与离线帖子.md`
- **设置按作用域分层**（`SettingsRepository`，见下）：

| Store | Key | 内容 |
|---|---|---|
| `settings_app` | `app` | `AppSettings` JSON：外观、启动、阅读、编辑器、缓存、分享、历史等**应用设置** |
| `settings_site` | host | `SiteSettings` JSON：Referer/人机验证、页面接管、字数上限、空间数据源、积分公式、快捷链接、默认用户、CDN |
| `settings_account` | `host\|uid` | `AccountSettings` JSON（预留账号级偏好） |
| `site_state` | `host\|kind` | 站点派生状态：表情缓存、作者资料等 |

- 读取统一走 `SettingsRepository.instance.app` / `.site(host)`（同步内存快照），不再在切站时把 per-site 值 push 到模块变量
- 新增设置项按作用域写对应模型；禁止再用 `setSetting('xxx')` 扁平键（MCP/窗口等独立控制器除外）
- MCP 令牌/端口与桌面窗口状态仍沿用旧 `app_settings` 扁平键（它们由独立控制器管理，不属于本次拆分范围）
- 站点身份（名称/baseUrl/UA/头像模板/版块）仍在 `app_sites` 的 `Site` 对象里
- Cookie 存储路径：`{appDataDir}/cookies/{host}/{accountName}`
- 缓存策略：设置/历史等 API 数据用 sembast，图片用 `flutter_cache_manager`

### 设置 / 账号 Cookie 导入导出

入口：关于页 →「数据管理」。两类文件互相独立，均支持剪切板与文件：

| 类型 | `format` | 内容 | 不含 |
|---|---|---|---|
| 设置 | `mtbbs.settings` | `AppSettings` + 各站点 `SiteSettings` | 缓存、账号、Cookie |
| 账号 Cookie | `mtbbs.cookies` | 各站点账号列表 + 游客/账号 CookieJar | 设置、缓存 |

- 设置导入会覆盖应用与站点设置文档，随后重新 `load()` 并 `applyRuntimeConfig()`（缓存天数、错峰间隔立即生效）
- Cookie 导入按站点/账号重建对应 `PersistCookieJar`，并重建会话；当前站点会重新恢复活跃账号
- **缓存永不导出**（图片、表情、帖子缓存都不在两类文件里）
- 实现：`lib/services/data_portability.dart`

## Dio 拦截器链

```
CookieManager → InterceptorsWrapper（统一日志 + 错误处理）
```

实际只有 CookieManager 与**一个**同时承担请求/响应日志与错误处理的 `InterceptorsWrapper`，没有独立的 `LogInterceptor`。

CookieManager 使用 `PersistCookieJar`，按 host + 账号隔离。
