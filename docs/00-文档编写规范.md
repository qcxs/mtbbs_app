# 文档编写规范

> 适用：新增/修改 `docs/` 与 `AGENTS.md` 时遵守。**写文档前先读本篇**——它定义"本项目的文档长什么样"。

## 一句话

**文档只回答「为什么这样做、会踩什么坑、去哪看」；怎么实现让读者读源码。**

## 读者与目标

读者是**没有任何上下文的 AI / 未来的自己**。目标只有两个：

1. 能在 30 秒内被**路由**到正确的一篇（入口是 `AGENTS.md` 的任务 → 文档路由表）
2. 读完能**做对事**，而不是复述一遍代码

## 固定结构

- 第 1 行是 `# 标题`
- 紧随一行引言块 `> 适用：<什么场景该读；是否「必读」>` —— **这是入口筛选器**，别人靠它决定要不要深入，不能省
- 标题最多三级；同级标题不重复表达同一件事
- 跨文档引用写 `见 docs/07 #26`（**编号是稳定 ID**，不要写"第 3 节""上文"）

## 写法

1. **一段话说清一件事**；列表只用于并列项与步骤，不用它排版散文
2. **只写增量**：源码里能读到的分步实现、推导过程、显而易见的结论，一律不写
3. **表格用于对照**（层级/职责/配置/取舍），不给散文套表格
4. **命令与配置片段逐字保留**，且必须可直接复制执行（含全部参数）
5. **禁止跨文档重复**：同一件事只在一处详述，其他处**指路**。已知权威：图片缓存规范在 `docs/01`、写操作协议在 `docs/12`、踩坑与诊断法在 `docs/07`
6. **坑写成"症状 → 根因 → 修法 → 教训"**（参考 `docs/07` 的条目风格），别只给结论
7. `docs/07-经验教训.md` 的**编号是稳定 ID**：新条目**只追加**、不重排、不改旧号 —— 否则所有引用点（其他文档、测试注释）都要跟着改

## 篇幅预算

| 类型 | 上限 | 超了怎么办 |
|---|---|---|
| 规范/概述类（01、02…） | ~150 行 | 拆篇，或把细节下沉到代码注释 |
| 流程/清单类（10~17） | ~150 行 | 删复述；命令与坑保留 |
| `docs/07` 单条经验 | 一段话 | 拆成两条编号 |

写不短，通常不是信息太多，而是**在复述源码**。

`docs/07` 例外：它是**编号检索表**，条数可以增长，受约束的是**单条长度**（一段话），不是总行数。

## 变更与索引

- **改代码同步改文档**：新增 API 三文件 → 更新 `docs/02` / `docs/11`；新增设置项 → 必须能"一句话从设置页走到"（见 `docs/07 #51`）
- 新增一篇文档，必须同步更新**两个索引**：`AGENTS.md` 路由表 + `README.md` 文档列表
- 失效内容**直接删除**，不留"此处原为…"式占位

## 提交前自检

- [ ] 命令可复制执行；表格与代码围栏配对
- [ ] 没有复述源码的分步讲解
- [ ] 与其他篇重复的详述已改为指路
- [ ] 未改动 `docs/07` 的既有编号
