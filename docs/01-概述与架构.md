# 概述与架构

> 适用：首次接触项目，理解分层架构、渲染管线、图片缓存规范与 Referer 策略。**必读。**

## 项目定位

Discuz + MT 论坛（克米模板）的 Flutter 客户端。Discuz 无官方 API，通过 `lib/api/` 层解析 HTML/XML 为结构化 JSON。

## 分层架构

```
lib/
├── main.dart              — 应用入口
├── api/                   — HTTP 请求 + HTML/XML 解析，三文件规范（http / parse / export）
├── auth/                  — 登录态管理
├── config/                — 全局配置（路由/工具栏/站点配置）
├── controllers/           — 控制器
├── core/                  — 核心基础设施
│   ├── parser/            —   解析器（BBCode、HTML→BBCode、帖子解析、线程列表、页面爬取、XML）
│   ├── utils/             —   工具（AppLogger、缓存管理、数据库、URL、快捷键、剪贴板）
│   ├── app/               —   应用基础设施（SiteStore、事件总线、表情加载、错峰队列、线程解析器）
│   ├── core_parsers.dart  —   barrel → parser/
│   ├── core_utils.dart    —   barrel → utils/
│   └── core_app.dart      —   barrel → app/
├── models/                — 纯数据模型（含 models.dart barrel）
├── providers/             — 有状态 UI 数据（ChangeNotifier + Provider）
├── services/              — 无状态业务逻辑（ApiService、MT图床）
├── pages/                 — 页面级 Widget，按功能拆文件
└── widgets/               — 可复用 UI 组件
    ├── bbcode/            —   BBCode 控件 + AST 渲染
    ├── thread/            —   帖子卡片/评论/网格
    ├── dialog/            —   弹窗/选择器
    ├── layout/            —   应用外壳/全局快捷键
    ├── common/            —   通用组件（头像/排行榜/RSS/PieChart）
    ├── image_preview/     —   图片查看器/画廊
    └── widgets.dart       —   顶层 barrel → 6 个子 barrel
```

## 渲染管线

```
Discuz 服务器 → API HTTP (Dio) → HTML/XML → parse 层 → 结构化数据 → Flutter Widget
                                                        ↓
                          BBCode → BBCode2Html → HTML → flutter_html → Widget
```

帖子内容链路：`bbcode → BBCode2Html → flutter_html`（[code]/[table] 还原为占位元素，flutter_html extension 原地替换为代码高亮/原生 Table，容器结构单次转换完整——见 docs/07 #31-36）。表情为两段式管线：parse 层 `Html2BBCode` 还原 `[呵呵]` 文本、渲染层 `BBCode2Html` 转 `<img>`（见 docs/07 #37-39）。

## 路由

GoRouter 实现，`lib/config/router.dart` 集中定义。AppShell 包裹底部导航（首页/导读/社区/我的），设置页嵌套子路由。

## 图片缓存规范

### 设计原则

App 主动管理图片缓存，**禁止**使用 Flutter 原生的 `Image.network()`（无磁盘缓存、不支持自定义请求头）。所有网络图片统一走 `CachedNetworkImage` + 自定义 `CacheManager`。

### 三层缓存管理器

```
IgnoreCacheFileService (Referer + 可配置过期)
        │
    ┌───┼───┐
    │   │   │
emoji  avatar  image
cache  cache  cache
```

所有管理器共用 `IgnoreCacheFileService`（`core/cache_utils.dart`），该服务：

1. **携带 Referer** — 每次 HTTP 请求自动添加 `Referer: SiteStore.instance.baseUrl`，模拟浏览器行为，绕过 Discuz 站点的防盗链检测
2. **忽略服务器 Cache-Control** — App 完全自主控制缓存过期时间（`stalePeriod`），不受响应头影响
3. **请求日志** — 每次下载输出 `[CACHE]` 日志

### 三个管理器的职责与配置

| 管理器 | Cache Key | 默认过期 | 覆盖范围 | 设置页管理 |
|--------|-----------|---------|---------|-----------|
| `emojiCacheManager` | `emoji_cache` | 永不过期 (-1) | 表情选择器、表情管理页 | ✅ 过期 + 清空 |
| `avatarCacheManager` | `avatar_cache` | 7 天 | 所有用户头像 | ✅ 过期 + 清空 |
| `imageCacheManager` | `image_cache` | 3 天 | 帖子图片、封面图、画廊、图床缩略图、快捷链接图标、成就徽章、表情、附件图标 | ✅ 过期 + 清空 |

### 集成规范

新增图片展示组件时，必须遵循以下优先级：

```dart
// ✅ 正确：使用指定缓存管理器
CachedNetworkImage(
  imageUrl: url,
  cacheManager: imageCacheManager,  // 根据场景选用对应管理器
)

// ❌ 禁止：无磁盘缓存、无 Referer
Image.network(url)

// ❌ 禁止：使用框架默认缓存（无 Referer）
CachedNetworkImage(imageUrl: url)  // 缺少 cacheManager 参数
```

### 初始化

`main.dart` 中调用 `initCacheManagers()`，传入用户的过期天数配置，在应用启动时重建所有管理器。

### 缓存管理页

`lib/pages/settings/cache_settings_page.dart` — 集中管理所有缓存：
- 查看各缓存磁盘占用和文件数
- 一键清空
- 独立设置过期天数（-1 永不过期 / 1~90 天）

## Referer 模拟策略

某些 Discuz 站点（如 52pojie.cn）对图片和 API 请求启用防盗链检查，要求请求携带 `Referer` 头。App 在三个层面统一添加：

| 层级 | 文件 | 机制 |
|------|------|------|
| API 请求 | `ApiService.init()` | Dio `BaseOptions.headers['Referer']`，站点切换时同步更新 |
| 图片缓存 | `IgnoreCacheFileService.get()` | `http.get()` 时添加 `Referer: SiteStore.instance.baseUrl` |
| 所有 `CachedNetworkImage` | 统一使用上述缓存管理器 | 自动继承 Referer |
