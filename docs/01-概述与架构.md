# 概述与架构

> 适用：首次接触项目，理解分层架构、渲染管线、图片缓存规范与 Referer 策略。**必读。**

## 项目定位

Discuz + MT 论坛（克米模板）的 Flutter 客户端。Discuz 无官方 API，通过 `lib/api/` 层解析 HTML/XML 为结构化 JSON。

## 分层架构

│   ├── app/               —   应用基础设施（SiteStore、事件总线、表情加载、错峰队列、线程解析器）
│   ├── core_parsers.dart  —   barrel → parser/

## 渲染管线

```
Discuz 服务器 → API HTTP (Dio) → HTML/XML → parse 层 → 结构化数据 → Flutter Widget
                                                        ↓
                          BBCode → BBCode2Html → HTML → flutter_widget_from_html → Widget
```

帖子内容链路：`bbcode → BBCode2Html → flutter_widget_from_html`。`[code]`/`[table]`/`[list]` 的处理方式：

- **`[table]`** — BBCode2Html 直接输出 `<table>` HTML，由渲染器**原生**渲染（自研 `HtmlTable`，支持 colspan/rowspan、列超宽自动横向滚动）。**不再需要"占位元素 + 按 table 分段"**
- **`[list]`** — 转换层展开为**带前缀的普通段落**（`<div>`），刻意不产出 `<ul>/<ol>/<li>`：渲染器的列表标记悬挂在文字左侧，每层嵌套都要吃掉一段水平空间，深层嵌套会把正文挤没
- **`[code]`** — BBCode2Html 还原为 `<div class="bbcode-code" data-code-index="N">` 占位元素，渲染层 `customWidgetBuilder` 按索引原地替换为 `BbcodeCodeBlock`（语法高亮 + 复制 + 语言切换）
- **图片** — `customWidgetBuilder` 返回 `InlineCustomWidget` 即**内联**（表情），返回普通 Widget 即**块级**（帖子图片）。链接手势会下沉包裹内部块级元素，因此点击图片能冒泡到 `[url]` 的点击事件

表情为两段式管线：parse 层 `Html2BBCode` 还原 `[呵呵]` 文本、渲染层 `BBCode2Html` 转 `<img>`（见 docs/07 #37-39）。

## 路由

GoRouter 实现，`lib/config/router.dart` 集中定义。AppShell 包裹底部导航（首页/消息/导读/我的），设置页嵌套子路由。「社区」是独立路由 `/forum`（`lib/config/router.dart` → `CommunityPage`），不在底部 Tab 中。

## 默认配置（assets/config，按域拆分）

启动时 `DefaultConfig.load()`（`lib/core/app/default_config.dart`）加载四个**按域拆分**的 JSON，
各文件**独立容错**——加载或解析失败只让该域返回空/默认，不影响其它域；只有站点配置带硬编码
回退（否则 App 无法启动）。

| 文件 | 域 | 顶层键 | 读取方 |
|---|---|---|---|
| `sites.json` | 站点 + 快捷链接 | `sites` / `shortcutLinks` | `defaultSites` / `shortcutLinksFor` |
| `toolbar.json` | 编辑器工具栏项（顺序/显隐/模板/默认快捷键） | `items` | `defaultToolbarItems` / `defaultToolbarShortcuts` |
| `shortcuts.json` | 全局快捷键 | `global` | `globalShortcuts` |
| `cache.json` | 图片缓存过期天数 | `expireDays` | `cacheExpireDays` |
| `quick_replies.json` | 帖子迷你编辑器常用语 | `items` | `defaultQuickReplies()` |

（`thanks.json` 为「特别感谢」名单，独立于以上默认值。）工具栏项的 `items` 语义见 docs/06「工具栏」。

## 图片缓存规范

### 设计原则

App 主动管理图片缓存，**禁止** Flutter 原生的 `Image.network()`（无磁盘缓存、不支持自定义请求头）；所有网络图片统一走 `CachedNetworkImage` + 自定义 `CacheManager`。

### 四层缓存管理器

所有管理器共用 `IgnoreCacheFileService`（`core/utils/cache_utils.dart`），该服务：

1. **携带 Referer** — 每次 HTTP 请求添加 `Referer: SiteStore.instance.baseUrl`，模拟浏览器行为，绕过 Discuz 防盗链检测；受「模拟浏览器请求头」开关控制（见「Referer 模拟策略」）
2. **忽略服务器 Cache-Control** — App 完全自主控制缓存过期时间（`stalePeriod`），不受响应头影响
3. **请求日志** — 每次下载输出 `[CACHE]` 日志
4. **穿过 WAF 挑战** — 手动跟随 3xx 跳转并按 host 回放 `Set-Cookie`，应对阿里云 ESA WAF（如 MT 图床 `icdn.binmt.cc`）的 307 挑战（详见 docs/07 #76）；论坛域那条链路（`acw_sc__v2` 挑战、两级恢复）见 `docs/20-人机验证与站点防护.md`

### 四个管理器的职责与配置

| 管理器 | Cache Key | 默认过期 | 覆盖范围 | 设置页管理 |
|--------|-----------|---------|---------|-----------|
| `emojiCacheManager` | `emoji_cache` | 永不过期 (-1) | 表情选择器、表情管理页 | ✅ 过期 + 清空 |
| `avatarCacheManager` | `avatar_cache` | 7 天 | 所有用户头像 | ✅ 过期 + 清空 |
| `imageCacheManager` | `image_cache` | 3 天 | 帖子图片、封面图、画廊、图床缩略图、快捷链接图标、表情、附件图标 | ✅ 过期 + 清空 |
| `medalCacheManager` | `medal_cache` | 永不过期 (-1) | 用户勋章（用户主页） | ✅ 过期 + 清空 |

### 集成规范

新增图片展示组件时，必须遵循以下优先级：

```dart
// ✅ 正确：使用指定缓存管理器
CachedNetworkImage(
  imageUrl: url,
  cacheManager: imageCacheManager,  // 根据场景选用对应管理器
)

// ❌ 禁止：无磁盘缓存、无 Referer
Image.network(url)

// ❌ 禁止：使用框架默认缓存（无 Referer）
CachedNetworkImage(imageUrl: url)  // 缺少 cacheManager 参数
```

### 初始化

`main.dart` 中调用 `initCacheManagers(emojiDays:, avatarDays:, imageDays:, medalDays:)`（四个命名必填参数），传入用户的过期天数配置，在应用启动时重建所有管理器。

### 缓存管理页

`lib/pages/settings/cache_settings_page.dart` — 集中管理所有缓存：
- 查看各缓存磁盘占用和文件数
- 一键清空
- 独立设置过期天数（-1 永不过期 / 1~90 天）

## 站点 CDN 自动识别

站点 CDN（表情等静态资源域名）**不由用户配置**，由 App 自动识别（站点换 CDN 域名时用户无需知情）：

- **来源**：Discuz 在**每个完整 HTML 页**的模板头部内联 `var STATICURL = '…'`（值来自 `config_global.php` 的 `$_config['output']['staticurl']`，见 `discuz_application.php`），该值即站点静态资源前缀。
- **探测页**：`GET /misc.php?mod=faq`（**PC UA**，标准 Discuz 路径、游客可见、体积最小），取不到时回退 `/forum.php`；实现见 `lib/api/site/cdn/`。**不用移动端页面**——克米模板跨站点不通用，而 `STATICURL` 是标准 Discuz 模板的通用输出。
- **取值**：`parseCdn()` 抽出 `STATICURL` 并归一为 `scheme://host`（与 `{cdn}/static/image/…` 拼接语义一致）；值为相对（站点未配 `staticurl`）或页面无 `STATICURL` 时返回 null → 回退站点 `baseUrl`。
- **时机**：启动与切换站点各后台探测一次（结果按 host 持久化，TTL 1 天）；设置 → 站点与网络 →「CDN 检测」可手动重测（不受 TTL 限制）。
- **生效点**：`SiteStore.cdnUrl` → `SiteCdnStore`（未识别到时回退 `baseUrl`）；表情图片 URL、头像模板 `{cdn}`、CDN 失败回退原站三处均取它。

## Referer 模拟策略

某些 Discuz 站点（如 52pojie.cn）对图片和 API 请求启用防盗链检查，要求请求携带 `Referer` 头。App 在三个层面统一添加：

| 层级 | 文件 | 机制 |
|------|------|------|
| API 请求 | `ApiService.init()` | Dio `BaseOptions.headers` 中**内联写入** Referer/Accept（受开关控制）；`refreshBrowserHeaders()` 负责运行时开关变更与站点切换时同步更新 |
| 图片缓存 | `IgnoreCacheFileService.get()` | `http.get()` 时按开关添加 `Referer: SiteStore.instance.baseUrl` |
| 所有 `CachedNetworkImage` | 统一使用上述缓存管理器 | 自动继承 Referer |

### 开关：设置 → 站点与网络 → 模拟浏览器请求头

默认开启。关闭后 API 与图片请求都不再发送 `Referer` 和 `Accept`，可用于排查跨站 Referer 被拒、或希望请求头更精简的场景；代价是部分站点会因防盗链拒绝图片。

开关状态放在 `api_service.dart` 的**模块级变量** `_simulateBrowserHeaders`（`applyBrowserHeaders()` 写入、`browserHeadersEnabled()` 读取），而不是 `ApiService` 的实例字段——因为 `SettingsProvider.load()` 早于 `ApiService.init()` 执行，那时 `dio` 还不存在。`init()` 读该变量构建请求头，`refreshBrowserHeaders()` 负责运行时变更与站点切换。

`User-Agent` 和 `X-Requested-With` **不受开关影响**：前者是独立设置项（「浏览模式」），后者决定 Discuz 是否按 AJAX 格式返回（去掉会拿到整页 HTML）。
