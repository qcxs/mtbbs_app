# 帖子缓存导出格式与自解析指南

> 适用：希望把 App 导出的帖子缓存用于备份、自建网页、脚本或第三方解析器的用户。本文只描述**导出 JSON**的格式与解析方法；缓存策略、损坏处理、管理页交互见 `docs/24-帖子缓存与离线帖子.md`。缓存与导出文件均为**明文、未加密**。

## 1. 这份导出文件是什么

- 由「设置 → 缓存管理 → 帖子缓存 → 导出」生成，包含**帖子标题、楼主正文、已缓存的评论页**。
- 每条记录是一次抓取时的**快照**：正文是当时看到的文本，评论是当时已加载的页。
- **不包含**图片二进制、附件二进制、表情图片、头像、登录 Cookie、formhash。
- 导出是 UTF-8、pretty-print 的普通 JSON，可直接用文本编辑器、脚本或网页读取。
- 不是站点完整备份：只能还原 App 当时能看到的公开/可见内容。

## 2. 如何导出与备份

| 动作 | 得到什么 | 用途 |
|---|---|---|
| 导出（自动缓存 Tab / 离线帖子 Tab） | `mtbbs_threads_{yyyyMMdd_HHmmss}.json` | 自解析、迁移、长期备份 |
| 导出原始文件 | `threads_{yyyyMMdd_HHmmss}.sembast` | 原样备份 App 缓存库；**不承诺第三方可解析** |
| 导入 | 读取上面的 JSON，写回 App 缓存库 | 恢复/迁移 |

- 导出范围跟随当前 Tab：自动 Tab 导出自动缓存，离线 Tab 导出离线副本；导入文件可以同时含两类。
- 原始 `.sembast` **只支持导出、不支持导入**；需要恢复时由用户在 App 未运行时手动替换文件。
- **明文提示**：文件包含用户名、IP 属地、正文与评论，请勿公开分享；不需要时及时删除。

## 3. 顶层结构

```json
{
  "format": "mtbbs.thread_cache",
  "schemaVersion": 1,
  "exportedAt": "2026-10-27T18:30:00+08:00",
  "appVersion": "1.0.0",
  "items": []
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `format` | string | 固定 `mtbbs.thread_cache`，用于识别文件类型 |
| `schemaVersion` | int | 当前为 `1`；结构冻结，见第 10 节 |
| `exportedAt` | string | 导出时间，ISO-8601 带时区偏移 |
| `appVersion` | string | 导出时的 App 版本，仅用于排查 |
| `items` | array | 快照对象数组，可同时包含 `auto` 与 `offline` |

`schemaVersion` 在顶层与每个快照内各出现一次；解析时以快照内的为准，但当前两者应相同。

## 4. 单条快照字段

`items` 的每个元素就是一份快照：

| 字段 | 类型 | 出现 | 说明 |
|---|---|---|---|
| `schemaVersion` | int | 必有 | 快照结构版本，当前 `1` |
| `kind` | string | 必有 | `auto`（自动缓存）或 `offline`（离线帖子） |
| `host` | string | 必有 | 站点域名，如 `www.example.com`；不同站点的 `tid` 不通用 |
| `viewer` | string? | 自动必有 | 抓取时的账号标识：登录用户 `uid:<uid>`，游客 `guest`；离线为 `null` |
| `savedBy` | string? | 离线必有 | 保存者展示标签（如 `uid:<uid>`），仅供管理页展示，不做鉴权 |
| `tid` | string | 必有 | 帖子 ID（字符串，避免大整数精度问题） |
| `title` | string | 必有 | 帖子标题（抓取时） |
| `contentHash` | string | 必有 | 标题 + 楼主正文的 FNV-1a 64 位哈希，见第 6 节 |
| `postTimeText` | string | 必有 | 楼主发布时间原文（如 `3 小时前`），仅供调试/判定，勿用于排序 |
| `isNewAtCapture` | bool | 必有 | 抓取时是否被判为新帖；离线副本记录保存时的判定 |
| `mainPost` | object | 必有 | 楼主帖，字段同第 5.3 节 `PostItem` |
| `commentPages` | object | 必有 | 评论页：键为页码字符串，值为 `PostItem` 数组；见 5.2 |
| `cachedPages` | int[] | 必有 | 实际已保存的页码，如 `[1, 2]`；升序 |
| `totalPages` | int | 必有 | 抓取时的总页数，供显示「已缓存 X/Y 页」 |
| `createdAt` | string | 必有 | 该快照第一次创建时间，ISO-8601 |
| `lastVisitedAt` | string? | 自动必有 | 最后一次成功访问/刷新时间；离线可能为 `null` |
| `expiresAt` | string? | 自动必有 | 自动缓存过期时间；离线固定 `null` |
| `savedAt` | string? | 离线必有 | 离线副本保存/覆盖时间；自动为 `null` |
| `approxBytes` | int | 必有 | 按 UTF-8 JSON 长度估算的大小，非数据库实际占用 |

排序建议：

- 自动缓存按 `lastVisitedAt` 倒序。
- 离线副本按 `savedAt` 倒序。
- 多条同 `tid` 的自动缓存是**不同正文版本**，不是重复项，见 5.4。

## 5. 正文、评论与版本

### 5.1 楼主帖

`mainPost` 是一个 `PostItem` 对象：

- `floor` 为 `0`，`isOp` 为 `true`。
- 正文在 `bbcode` 字段，是 Discuz BBCode 文本，不是 HTML。
- 标题取快照的 `title`，不在 `mainPost` 内重复。

### 5.2 评论分页

```json
"commentPages": {
  "1": [ { "pid": "1000002", "floor": 1, "...": "..." } ],
  "2": [ { "pid": "1000020", "floor": 21, "...": "..." } ]
}
```

- **键是页码字符串**（JSON 对象键只能是字符串）；`"1"` 对应第 1 页。
- 第 1 页的数组**不含楼主**，只含该页评论，与 App 页面一致。
- **缺失的页 = 未缓存**，不要伪造空数组。
- **空数组 = 该页已缓存但没有评论**，与缺失不同。
- `cachedPages` 与 `commentPages` 的键应一一对应；`totalPages` 是抓取时的总页数。
- 自动缓存只保存用户**实际加载过**的页；离线副本可能完整，也可能只有前几页（保存时用户选择「仅保存已加载」或中途取消）。
- 评论页可能因站点删帖、权限变化而在之后失效，但快照保存的是抓取时的内容。

### 5.3 `PostItem` 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `pid` | string | 帖子/楼层 ID；解析降级时可能为空 |
| `floor` | int | 楼层号；楼主为 `0` |
| `floorLabel` | string | 楼层显示名，如 `沙发`、`板凳`；普通数字楼层可能为空 |
| `isOp` | bool | 是否楼主帖 |
| `uid` | string | 作者 UID；游客/匿名可能为空 |
| `username` | string | 作者显示名 |
| `usergroup` | string | 用户组文案，如 `普通会员` |
| `postTime` | string | 发布时间原文，可能是相对时间（`3 小时前`）或完整日期；**不稳定，勿用于排序/去重** |
| `ipLocation` | string | IP 属地（站点开启时才有） |
| `source` | string | 来源文案（如「来自手机」），可能为空 |
| `bbcode` | string | 正文 BBCode；见第 7 节 |
| `followUrl` | string | 「关注」操作地址；可能为空/需登录 |
| `recommendUrl` | string | 「评分」操作地址；可能为空/需登录 |
| `favoriteUrl` | string | 「收藏」操作地址；可能为空/需登录 |
| `kickUrl` | string | 「顶/踩」操作地址；可能为空/需登录 |
| `isLiked` | bool | 抓取时是否已点赞/已顶 |
| `rating` | object? | 评分记录，见下 |
| `degraded` | bool | 该楼层解析失败、降级为占位；此时 `bbcode` 可能为空，不建议当正常正文展示 |
| `stamp` | string | 主题印章（如 `精华`），通常只在楼主帖 |
| `isStickReply` | bool | 是否为管理员置顶回复（评论） |

`rating` 结构：

```json
{
  "header": "评分",
  "detailUrl": "https://www.example.com/forum.php?mod=misc&action=viewratings&tid=987654&pid=1000002",
  "totalScore": " +5 ",
  "entries": [
    { "username": "李四", "uid": "23456", "score": " +5 ", "reason": "感谢分享" }
  ]
}
```

展示约定：

- `floorLabel` 非空且不含数字时，App 直接显示它（如 `沙发`）；否则显示 `#<floor>`。
- 操作 URL 是站点原始地址，可能过期或需要登录；只读解析时不要主动请求。
- `degraded` 为 `true` 时，建议显示「该楼层解析失败」而不要渲染空正文。

### 5.4 版本与身份

| 类型 | 身份（键） | 版本数 | 说明 |
|---|---|---|---|
| 自动缓存 | `auto\|{host}\|{viewer}\|{tid}\|{contentHash}` | 同一帖子最多 3 个正文版本 | 正文不变时只更新同一版本的评论与时间 |
| 离线帖子 | `offline\|{host}\|{tid}` | 每帖 1 份 | 覆盖保存会整体替换 |

- 自动缓存出现多条同 `tid` 记录是正常的：`contentHash` 不同 = 作者改过正文（例如改成「已删除」），旧版本保留以便回看。
- 自动缓存只保留最近 3 个**正文版本**；不是保留 3 次访问。
- 正文不变、仅评论变化时，不会新增版本，只更新 `commentPages`、`lastVisitedAt`、`expiresAt`。
- 离线副本不参与版本裁剪，也不会被自动过期清理。

## 6. 复算 `contentHash`

定义：

```
contentHash = FNV-1a-64( UTF-8( normalize(title) + "\x00" + normalize(mainPost.bbcode) ) )
```

`normalize` 规则：

1. `\r\n` → `\n`。
2. 去掉首尾空白（`trim`）。
3. **不折叠内部空白**，否则 `[code]` 的缩进差异会被误判为同一内容。

输出为 16 位小写十六进制。该哈希只用于分键/去重，**不是安全校验**。

JavaScript 参考实现：

```js
const encoder = new TextEncoder();

function fnv1a64(str) {
  let hash = 0xcbf29ce484222325n;
  const prime = 0x100000001b3n;
  const mask = 0xffffffffffffffffn;
  for (const byte of encoder.encode(str)) {
    hash ^= BigInt(byte);
    hash = (hash * prime) & mask;
  }
  return hash.toString(16).padStart(16, '0');
}

const normalize = (s) => (s ?? '').replace(/\r\n/g, '\n').trim();

function contentHashOf(snapshot) {
  return fnv1a64(
    normalize(snapshot.title) + '\u0000' + normalize(snapshot.mainPost.bbcode)
  );
}
```

注意：

- `\u0000` 是分隔符，必须保留。
- 不要包含 `postTime`、`ipLocation`、`isLiked`、`rating` 等易变字段；否则每次访问都可能产生「新版本」。
- Dart 的 `String.hashCode` 跨进程不稳定，不能替代此算法。

## 7. 渲染 `bbcode`

### 7.1 基本约定

- `bbcode` 是 **Discuz BBCode 纯文本**，不是 HTML。直接塞进网页前必须做 HTML 转义（`& < > " '`）。
- 换行是字面 `\n`。App 将 `\n` 渲染为 `<br>`，并把连续 3 个以上换行折叠为最多 2 个。
- 常见标签：

| 类别 | 标签 | 说明 |
|---|---|---|
| 样式 | `[b]` `[i]` `[u]` `[s]` | 粗/斜/下划/删除线 |
| 样式 | `[color=red]` `[backcolor=#eee]` `[size=4]` `[font=Arial]` `[align=center]` | 颜色、背景、字号、字体、对齐 |
| 链接 | `[url]https://…[/url]` `[url=https://…]文字[/url]` `[email]…[/email]` `[qq]123456[/qq]` | 链接、邮箱、QQ |
| 媒体 | `[img]URL[/img]` `[img=W,H]URL[/img]` `[audio]URL[/audio]` `[media]URL[/media]` `[flash]URL[/flash]` | 图片、音频、视频/Flash 占位 |
| 结构 | `[quote]` `[code]` `[hide]` `[free]` `[list]` `[list=1]` `[table]` `[tr]` `[td]` `[hr]` | 引用、代码、隐藏、免费信息、列表、表格、分割线 |
| 特殊 | `[appdata]{…}[/appdata]` | App 解析器生成的附件/投票/悬赏等结构，见 7.2 |
| 表情 | `[呵呵]` 或 `[emoji_12]` | 表情文本；导出不含表情图片映射，见 7.4 |

### 7.2 `[appdata]` 结构化内容

附件、图片附件、投票等被 App 转成一段 JSON：

```
[appdata]{"type":"image_attach","url":"https://…","aid":"1","name":"1.jpg"}[/appdata]
```

先于普通 BBCode 解析：匹配 `\[appdata\]([\s\S]*?)\[\/appdata\]`，把中间内容按 JSON 解析。已知 `type`：

| `type` | 字段 | 含义 |
|---|---|---|
| `image_attach` | `url` `aid` `name` `size?` `downloads?` `uploadTime?` | 图片附件 |
| `attach` | `aid` `name` `size?` `downloads?` `url` | 普通附件（下载链接） |
| `locked` | `message` | 需付费/权限查看的提示 |
| `pstatus` | `message` | 帖子状态提示 |
| `reward` | `amount` `unit` | 回帖奖励 |
| `bounty` | `amount` `unit` | 悬赏 |
| `poll` | `pollType` `voterCount` `options[]` `status` | 投票 |

未知 `type` 建议忽略或显示「不支持的内容」，不要把 JSON 原文直接插进 HTML。

### 7.3 代码、引用、隐藏

- `[code]…[/code]`：内部是**代码原文**，不要再解析 BBCode、URL 或表情；按等宽字体、保留空白显示。
- `[quote]…[/quote]`：引用块。
- `[free]…[/free]`：免费信息块。
- `[hide]…[/hide]` / `[hide=…]…[/hide]`：App 显示「隐藏内容」标签 + 内容（内容已在快照中，不需要再登录）。
- `[list]` / `[list=1]` / `[list=a]`：App 渲染为带前缀的段落；网页可以转成 `<ul>/<ol>`。
- `[table]` / `[tr]` / `[td]`：App 用原生表格渲染，建议转成 `<table>`。

### 7.4 图片、链接、表情与附件边界

- `[img]` 与 `appdata` 里的图片/附件 URL 在抓取时已尽量归一化为绝对地址。
- `[url=…]` 的链接**可能仍是站点相对地址**（如 `forum.php?mod=viewthread&tid=1`），请用 `https://{host}/` 补全。
- 图片是否能直接打开取决于站点防盗链：App 请求图片时会带 `Referer: {站点根地址}`，自建网页可能需要在图片代理里补同样的 Referer 和登录 Cookie，否则可能 403。
- 导出**不含图片文件**；原图被删除、附件过期或图片缓存清理后，只读快照仍会显示文本，但图片可能加载失败。这是文本缓存的既定边界。
- 表情：BBCode 中可能是 `[呵呵]` 这类文本，也可能是 `[emoji_N]`。导出不含站点表情表，网页可原样显示为文本，或自行从站点获取表情映射。
- `[attach]` 等未识别的 Discuz 标签：按纯文本保留，或显示为「附件」占位，不要执行其中的内容。

## 8. 最小网页解析示例

目标：读取导出文件，选一条离线副本，把楼主和评论显示为纯文本。

```js
const data = JSON.parse(await file.text());
const item = data.items.find((x) => x.kind === 'offline');

function bbcodeToText(bbcode) {
  return String(bbcode ?? '')
    .replace(/\[code\]([\s\S]*?)\[\/code\]/gi, (_, code) => `\n${code}\n`)
    .replace(/\[appdata\]([\s\S]*?)\[\/appdata\]/gi, '[附件/特殊内容]')
    .replace(/\[img[^\]]*\]([\s\S]*?)\[\/img\]/gi, (_, url) => `[图片] ${url}`)
    .replace(/\[url=([^\]]+)\]([\s\S]*?)\[\/url\]/gi, (_, href, text) => `${text} (${href})`)
    .replace(/\[url\]([\s\S]*?)\[\/url\]/gi, (_, href) => href)
    .replace(/\[(?:\/)?(?:b|i|u|s|quote|free|hide|list|table|tr|td|align|color|size|font|backcolor)(?:=[^\]]*)?\]/gi, '');
}

function renderPost(post, title) {
  const box = document.createElement('section');
  const h = document.createElement('h3');
  h.textContent = `${title ?? ''} · ${post.username} · ${post.postTime}`;
  const body = document.createElement('pre');
  body.style.whiteSpace = 'pre-wrap';
  body.textContent = bbcodeToText(post.bbcode);
  box.append(h, body);
  return box;
}

document.body.append(renderPost(item.mainPost, item.title));
for (const page of item.cachedPages) {
  for (const post of item.commentPages[String(page)] ?? []) {
    document.body.append(renderPost(post));
  }
}
```

要点：

- 用 `textContent` 而不是 `innerHTML`，避免正文里的 HTML/脚本被执行；若必须用 `innerHTML`，先做完整转义。
- 评论页按 `cachedPages` 遍历，不要假设 `1..totalPages` 都存在。
- 只读展示时不要请求 `followUrl` / `recommendUrl` 等操作地址。

## 9. 导入回 App

导入文件必须是本文格式的 JSON，且顶层 `format` 为 `mtbbs.thread_cache`、`schemaVersion` 为 `1`。

校验与处理：

1. 限制文件大小（约 100 MB），避免误选大文件。
2. 顶层字段不符 → 整份拒绝。
3. 逐条校验 `kind`、`host`、`tid`、`title`、`mainPost`、`commentPages` 等必填字段；单条损坏只跳过该条，不中断整份导入。
4. `approxBytes` 超过单帖上限（默认 4 MiB）→ 跳过该条。
5. **自动缓存**：`viewer` 改写为当前账号（游客 `guest`），使导入后立即可见；`lastVisitedAt` 置为导入时间，`expiresAt = 导入时间 + 当前缓存天数`，避免刚导入就过期；保留原 `createdAt`。
6. **离线副本**：保留 `savedBy`、`savedAt`；同 `(host, tid)` 冲突时询问「覆盖全部 / 跳过全部」。
7. 自动缓存同键冲突时保留较新的版本，较旧跳过。
8. 导入**不发起网络请求**，不解析 HTML，不执行 BBCode/脚本，也不写主数据库。

导入结果会给出成功、跳过、失败数量与原因分类。

## 10. 稳定性与隐私

- **v1 结构冻结**：后续只允许追加可选字段，不改字段名/类型/含义、不调整嵌套层级；解析器应忽略不认识的字段。
- `schemaVersion` 保持 `1`；只有发生破坏性变更才提升版本，并会提供显式迁移/导出方案。
- **不加密是长期约定**：缓存库与导出文件都保持明文，不引入密钥或平台安全存储。
- 文件包含站点域名、账号标识、用户名、IP 属地、正文与评论，属于**隐私数据**：
  - 不要上传到公开网盘、GitHub、聊天群；
  - 分享前请手动删除不需要的条目；
  - 自建网页若对外提供访问，请加访问控制，避免正文与用户信息被公开索引。
- 导出中的图片/附件只是 URL，不保证长期有效；需要长期保存图片请自行下载。

## 11. 常见问题

**为什么同一帖子有多条自动缓存？**
`contentHash` 不同，说明抓取时正文不同（例如作者先正常发帖，后改成「已删除」）。自动缓存最多保留 3 个正文版本。

**为什么评论只有 1/5 页？**
自动缓存只保存你实际加载过的评论页；离线副本也可能在保存时选择「仅保存已加载」或中途取消。缺失页不会被伪造。

**为什么 `postTime` 是「3 小时前」而不是日期？**
快照保存的是抓取时页面上的原文。相对时间会随时间变化，不要用它排序或判断版本。

**图片为什么打不开？**
导出不含图片文件，且站点可能有防盗链/登录限制。App 请求图片时会带 Referer；自建网页需要自行处理。

**可以修改 JSON 后再导入吗？**
可以，但必须保持字段结构与类型；`contentHash` 与正文不一致可能导致被当作不同版本或校验失败。修改后建议自行复算 `contentHash`。

**能导入 `.sembast` 原始文件吗？**
不能。原始文件只用于导出备份；恢复需在 App 未运行时手动替换。

**缓存文件损坏了，导出还能用吗？**
管理页提供「导出原始文件」和「尽力导出 JSON」。前者是原样备份，后者会跳过无法解析的记录；是否导出由你决定。
