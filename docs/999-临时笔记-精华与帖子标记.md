# 999 临时笔记：精华聚合 + 帖子列表标记族谱

> 适用：再次排查「导读精华为空 / 列表区分不出精华 / 想给列表加徽标（置顶、推荐、热度、附件…）」时**先读本篇**，省去重新抓包与翻 Discuz 源码。**临时文档**，要点稳定后应并入 `docs/03` 或 `docs/07`；不进正式索引。

## 1. 导读「最新精华」为什么经常为空

`forum.php?mod=guide&view=digest` → `source/module/forum/forum_guide.php::get_guide_list('digest')`，实际过滤条件：

```
digest>0
AND displayorder>=0
AND tid > maxtid - 50000
AND fid IN (公开版块: type!=group/status>0/无 viewperm/无密码)
AND dateline > now - digestdt      ← ★ 关键：精华聚合时间范围
```

`digestdt` = 后台「**精华聚合时间范围**」（站点功能 → 导读；`admincp_setting.php` 的 `setting_functions_guide_digestdt`）。**Discuz X3.5 装完默认就是 7 天**：

```
install/data/install_data.sql:  guide = 'a:2:{s:5:"hotdt";i:604800;s:8:"digestdt";i:604800;}'
```

后台下拉只有 **7/14/30/90/180/365 天，没有「不限」**。MT 精华帖产出稀疏（实测最近一篇发布于 2026-9-7），窗口内一旦没有新精华帖，该列表恒为空——**不是数据丢失，也不该动 App**。（导读另有 900s 结果缓存，`$_G['cache']['forum_guide']`。）

## 2. 查「全部精华帖」的可靠入口（不受时间窗限制）

- **站内搜索**：`GET /search.php?mod=forum&searchsubmit=yes&srchfilter=digest`（`srchfilter ∈ all/digest/top`，**允许无关键词**，`submitcheck(...,1)` 的 allowget 分支免 formhash）。App 已接入：「我的 → 精华帖」→ `/search/result?filter=digest`。
- **版块内精华**：`forum.php?mod=forumdisplay&fid=X&filter=digest&digest=1`。
  - ⚠️ `filter=digest` **单独不生效**——Discuz 靠**名为 `digest` 的参数**设 `$filterarr['digest']`（`forum_forumdisplay.php` L415-420）；**推荐同理要 `&recommend=1`**。App 的 `lib/api/forum/forumdisplay/http.dart` 已自动补这两个参数。
- **精华列表里服务端会抑制精华徽标**：`forumdisplay_list.htm` 的 `span.tbox.tdigest` 带条件 `$filter != 'digest'`，故「精华列表里解析不到 digest」属正常。
- `forum.php?mod=guide&view=digest&rss=1` 与导读**同源**，同样受 `digestdt` 限制，不能当替代。

## 3. 帖子列表标记族谱

出处：标准 PC 见 `template/default/forum/forumdisplay_list.htm`；克米两套为**实测 MT DOM**。

| 模板 | 精华 | 其它标记（可直接用的选择器） |
|---|---|---|
| **标准 Discuz PC**（`#threadlist tbody[id^=normalthread_]`） | 标题列 `span.tbox.tdigest`（文本「精华 N」） | 推荐 `span.trecic`(title="推荐 N")、热度 `span.theatlevel`(title="热度: N")、置顶 `td.icn i.tpin.tpin{1..4}`、关闭 `i.fico-lock`、专题 `i.fico-vote/cart/reward/group/vs`(投票/商品/悬赏/活动/辩论)、图片附件 `i.fico-image`、附件 `i.fico-attachment`、评分 `i.fico-thumbup/thumbdown`、印章 `img src=.../image/stamp/*`、`New`(周内 `a.xi1`)、多页 `span.tps`、隐藏 `span.xg1`、抢楼 `span.tbox.rushrep` |
| **克米 PC 表格**（`.comiis_postlist .comiis_common`） | **不渲染**（见 §4） | 图片附件 `img[alt=attach_img]`、附件 `img[alt=attachment]`、热度 `img[alt=heatlevel]`(title="热度: N")、推荐 `img[alt=recommend]`、加分 `img[alt=agree]`、印章 `img[src$=.small.gif]`(alt=印章文本，如 新人帖/推荐)、多页 `span.tps` |
| **克米移动卡片**（`li.forumlist_li.comiis_znalist`，标题 `<a>` 内的**前置 `<span>`**） | `<span class="bg_c f_f">精</span>` | 推荐 `<span class="bg_c f_f" title="荐 N">荐</span>`、热度 `<span class="bg_a f_f" title="热度: N"><i class="comiis_font kmhotico"></i></span>` |
| **标准 Discuz 搜索**（`#threadlist li.pbw`） | **无** | 无（标题/摘要/作者/版块，无任何徽标） |

## 4. 关键事实（易踩）

- **MT 的克米 PC 列表根本不渲染精华徽标**：多版块验证（fid=41/42/46，含已知精华帖 `tid=85763` 总版规），`td.icn` 与标题处均无 digest 痕迹 → **MT PC 端无法从列表区分精华**；只有克米**移动卡片**显示「精」。
- 标准 PC 的精华徽标文本是「精华N」（`{lang thread_digest}` + 等级数字）。
- 克米移动和 PC 的徽标类名（`bg_c f_f` 等）是**通用配色类**，不含语义，只能靠**文本**（「精」/「荐」）或 **title 属性**（`热度: N`/`荐 N`）区分。
- 克米移动卡片的标题清洗已 `excludeTags: {'span','i'}`，徽标不会混入标题。
