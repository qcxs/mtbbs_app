# 应用图标

> 适用：改图标、调图标比例、换配色、重新生成各尺寸位图。按需。

只记录**设计源、关键几何数值、比例规则与重新生成方式**。改图标前必读，避免又把字标拉变形。

## 一、设计源与产物

**唯一设计源**：`assets/icon/ic_mt.svg`（白 mt 字标，2242×2242 方形 viewBox）。
比例评审图：`assets/icon/ic_launcher_spec.png`（含安全区标注与三方案对比）。
注意：`assets/icon/` 未登记进 `pubspec.yaml` 的 `assets:`，**不会打进包**，纯粹是设计源。

产物与去向：

| 产物 | 路径 | 用途 |
|------|------|------|
| 背景色 | `android/.../res/values/colors.xml` → `ic_launcher_background` | 自适应背景层，`#000000` |
| 前景矢量 | `android/.../res/drawable/ic_launcher_foreground.xml` | 自适应前景层，白字标 |
| 自适应装配 | `android/.../res/mipmap-anydpi-v26/ic_launcher.xml` | API 26+ 走这个 |
| 旧式回退 | `android/.../res/mipmap-{m,h,xh,xxh,xxxh}dpi/ic_launcher.png` | API < 26 |
| Windows | `windows/runner/resources/app_icon.ico` | 16/32/48/64/128/256 多尺寸 |
| 应用内展示 | `assets/icon/app_icon.png` | 关于页头部，`mipmap-xxxhdpi/ic_launcher.png` 的副本 |

`assets/icon/app_icon.png` 是**副本**，不是另一次渲染：关于页要显示图标，而 Flutter 引用不到 `android/app/src/main/res/`，只能往 assets 放一份。改图标时这两处要一起换（见第六节）。

提示：**不要**给应用内图标做 1x/2x/3x 变体。源图只有 192px，3x 需要 216 得放大；只出 1x(72)+2x(144) 时 3x 屏会拿 144 放大到 216，比直接用 192 更糊。单张 192px 最优。

背景是**纯色**，所以用 color 资源而不是 108×108 的 vector；要改渐变/花纹再换成 drawable。

## 二、字标的真实几何（一切比例的出发点）

从 SVG 量出来的实测值，不是估算：

```
墨迹 bbox    x[81, 2160]  y[635, 1606]   →  2079 × 971
宽高比       2.1411
在 viewBox   水平占 92.7%、垂直占 43.3%，完全居中
```

**它是个 2.14:1 的横向字标，不是方形图形。** 这决定了两件事：

1. 缩放的唯一约束是"落在安全区内"，纵向永远不紧张，横向才是瓶颈；
2. 任何非等比缩放都会立刻被看出来（16.7% 的纵向拉伸就足以让字形明显变胖）。

## 三、自适应图标（Android 8+）比例

官方画布与安全区：

```
画布            108 × 108 dp
安全方区        中央 72 × 72 dp（官方保障可见）
圆形蒙版安全区  中央 ⌀66dp（最严苛；Pixel 等圆形蒙版按这个判定）
外层            每边 18dp，会被蒙版裁掉，属预期
```

**采用的方案**：字标等比缩放到四角正好内切 ⌀66dp 安全圆。

```
字标尺寸    59.7993 × 27.9293 dp   （占画布宽 55.4%）
在 ⌀72dp 可见圆里占宽 83%，不会显小
```

落地为 [ic_launcher_foreground.xml](../android/app/src/main/res/drawable/ic_launcher_foreground.xml)：

```xml
<group android:scaleX="0.597108452"
       android:scaleY="0.597108452"     <!-- 必须与 scaleX 相等 -->
       android:translateX="451.93998"
       android:translateY="451.93998">
```

**变换语义**（Android `VectorDrawable` 的 group 与 SVG 的 `translate(...) scale(...)` 完全一致，都是 `p' = p × scale + translate`，pivot 为 0）：

```
s  = 目标宽度dp / 108 × 2242 / 2079        （2079 = 墨迹宽）
t  = 1121 − 1120.5 × s                     （1121 = 画布中心，1120.5 = 墨迹中心）
```

因为墨迹水平垂直中心都是 1120.5，所以 `translateX == translateY`。

想换大小，只改 `s` 与 `t`，两轴永远相等。参考值：

| 目标 | 字标尺寸 | 占画布宽 | 说明 |
|------|---------|---------|------|
| 内切 ⌀66dp 圆（当前） | 59.80 × 27.93 dp | 55.4% | 任何蒙版都不裁切 |
| 内切 ⌀72dp 圆 | 65.24 × 30.47 dp | 60.4% | 更饱满，但圆蒙版下四角贴边 |

## 四、非自适应位图比例（Android < 26 + Windows）

没有蒙版，图案直接铺满，所以是"黑圆角方 + 白字标"：

```
背景      黑色 #000000，圆角方铺满整张（圆角半径 = 边长 × 22%）
字标      宽 = 画布宽 × 68.8%（沿用旧图标的光学比例），居中，等比
```

尺寸：Android mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi = 48/72/96/144/192 px；Windows ico 出 16/32/48/64/128/256。

## 五、踩过的坑

| # | 坑 | 症状 | 正确做法 |
|---|----|------|---------|
| 1 | 前景 `scaleX=0.5228571` / `scaleY=0.61` 不等 | 字标被**纵向拉伸 16.7%**，宽高比由 2.141 变 1.835；而线上旧图标实测宽高比 2.155，两者对不上——说明这份前景从未真正生效 | 两轴永远相等，只调大小 |
| 2 | 背景直接沿用 Flutter 模板 | `#3DDC84` 绿底 + 一堆 `#33FFFFFF` 网格**参考线**被当成正式背景 | 纯黑 `#000000`，网格线是模板辅助线，必须删 |
| 3 | 5 个密度目录塞同一张 545px PNG | 所有设备实际只拿到 1x 资源，144/192px 场景被系统拉伸；5 份重复共 2.6MB | 按密度出对应像素，单张最大 5KB |
| 4 | 原 SVG `width="65.4" height="76.3"` 与方形 viewBox 不符 | 直接用会按 65.4:76.3 的框渲染，字标被 letterbox 缩小 | 素材一律用 `viewBox` + `preserveAspectRatio="xMidYMid meet"` 渲染到方形画布，忽略 width/height |
| 5 | 把"缩放"理解成"撑满可用宽高" | 横向字标撑满宽后四角远在安全圆外，圆形蒙版机型会切掉 m 和 t 的端部 | 约束是**落在安全区内**，不是撑满 |

## 六、重新生成

机器上 **PIL 不支持 SVG**（无 cairosvg/svglib），光栅化走**无头 Chrome**，再用 PIL 降采样。

```powershell
# 1. 把 SVG 内联进 HTML，尺寸由 window-size 控制，透明底
#    svg{display:block;width:100vw;height:100vh} + preserveAspectRatio="xMidYMid meet"
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --headless=new --disable-gpu --hide-scrollbars --no-first-run `
  --default-background-color=00000000 --force-device-scale-factor=1 `
  --virtual-time-budget=4000 --window-size=1024,1024 `
  --screenshot="legacy_1024.png" "file:///.../legacy.html"

# 2. PIL 降采样到各目标尺寸
#    圆角方用 <rect rx> 画；多尺寸 ico 用 Pillow 的 sizes=
big.save("app_icon.ico", format="ICO",
         sizes=[(16,16),(32,32),(48,48),(64,64),(128,128),(256,256)])

# 3. 应用内图标不用再渲染，直接复制 xxxhdpi 那一张
Copy-Item android\app\src\main\res\mipmap-xxxhdpi\ic_launcher.png assets\icon\app_icon.png
```

`--default-background-color=00000000` 是透明底的关键，否则圆角处会是白底。

## 七、生成后的校验

不要凭肉眼看，量墨迹 bbox：

```
自适应：1024 画布 → 字标 566 × 264 px，中心 (512, 512)
        （59.7993/108×1024 = 567，误差 1px 内）
非自适应：1024 画布 → 字标宽 704 px（= 1024 × 0.688），中心 512
```

再跑一次构建确认资源能编译（矢量 XML 写错只会在打包期报错）：

```bash
flutter build apk --debug
flutter build windows --debug
```
