# 开发规范

> 适用：新增/修改 API、文件、UI 时遵守的开发约定。**必读。**

## API 新增流程（8 步）

1. 分析目标页面 → 确定 URL 和参数
2. `lib/api/{name}/` 下创建三个文件
3. `http.dart` — 发送请求，只做 `dio.get/post`，**不允许**调 parse
4. `parse.dart` — 纯函数解析 HTML/XML → JSON，**不包含**网络逻辑
5. `tool/api_scenarios.dart` 注册探针场景，用 `flutter test tool/api_probe_test.dart --dart-define=cmd={name}` 真实请求验证（见 `docs/10-API探针使用规范.md`、`docs/11-新增功能开发流程.md`）
6. `export.dart` — 导出 `fetchXxx` 便捷方法
7. 挂载到 Flutter 服务层（`services/` 或页面层调 export）
8. 验证

## 数据层 ↔ 渲染层职责边界

**一句话：数据层产出"可直接使用"的值，渲染层只消费、不修正。**

| | 数据层（`lib/api/` 的 parse/export、`core/parser/` 的转换器） | 渲染层（`lib/widgets/`） |
|---|---|---|
| 职责 | 把 Discuz 的脏数据加工成渲染层能直接用的值 | 拿到什么就渲染什么 |
| 必须做 | 相对地址补全域名、HTML 实体解码、非法值丢弃/归一化（如 `BBCode2Html._normalizeColor`）、索引与列表字段一一对应 | **越界/缺省防护**：索引越界返回空组件、缺省退化为单图或默认样式，**不允许崩溃** |
| 禁止 | — | 不 `htmlUnescape`、不拼 `baseUrl`、不猜格式、不写"如果是相对路径就…"式兜底 |

判断标准：渲染层出现"这是不是需要修正一下"的念头时，**改数据层**。正例：`[code]` 越界返回空组件（docs/07 #31）、无限宽约束下退化布局（docs/07 #45）；反例见下方「禁止序列化再读回」。

### 禁止：把自己的输出序列化后再读回来

需要交给渲染层的**结构化数据**（URL 列表、代码原文、索引…），必须在**产出 HTML 的同一处**记录成公开字段（发射点记录），**不要**在生成的 HTML 上做正则二次读取：

```dart
// ✅ 发射点记录：url 与 tag 同源，只写一次
String _emitContentImage(String url, String tag) { ... }   // → imageUrls

// ❌ 生成 HTML 后再正则回读：写入时的转义/属性顺序一变就静默取到错值
final src = RegExp('src="([^"]*)"').firstMatch(tag)?.group(1);
imageUrls.add(unescapeHtml(src));   // 一次"修补"就是一次事故伏笔
```

原因：HTML 是**转义过的**字符串（`&` → `&amp;`），而渲染器解析后拿到的是**已解码**的值，两边取值方式不同就会漂移——`[img]` 与 `[appdata]` 图片地址内联正常、画廊全黑就是这么来的（docs/07 #68）。

实现范式参考 `[code]`：占位符（`\x00CODE*`）先落位、最后统一展开，顺便让**列表顺序 = 文档顺序**；`[img]` 同理（`\x00IMG*` → `data-img-index` + `imageUrls`）。

## Import 规范

**统一使用 `package:mtbbs/...` 绝对路径导入**，禁止相对导入（`../`、`../../`）。

```dart
// ✅ 正确
import 'package:mtbbs/core/app/site_store.dart';
import 'package:mtbbs/core/utils/logger.dart';
import 'package:mtbbs/config/config.dart';
import 'package:mtbbs/widgets/bbcode/bbcode_toolbar.dart';
import 'package:mtbbs/widgets/common/user_avatar.dart';
import 'package:mtbbs/widgets/layout/app_shell.dart';
import 'package:mtbbs/widgets/dialog/rate_dialog.dart';

// ❌ 禁止
import '../../core/site_store.dart';
import '../../../widgets/user_avatar.dart';
import 'core/logger.dart';
```

例外：barrel 文件的 `export` 使用同目录相对路径。

```dart
// barrel 文件 (如 widgets/bbcode/bbcode.dart)
export 'bbcode_toolbar.dart';        // 同目录，✅
```

### barrel 文件速查

| barrel 文件 | 用途 |
|---|---|
| `config/config.dart` | 聚合 6 个配置 |
| `models/models.dart` | 聚合 9 个 model |
| `widgets/widgets.dart` | 顶层 → 6 个子 barrel（bbcode/thread/dialog/layout/common/image_preview；`widgets/editor/` 未纳入 barrel） |
| `core/core_parsers.dart` | barrel → parser/ |
| `core/core_utils.dart` | barrel → utils/ |
| `core/core_app.dart` | barrel → app/ |

## 文件命名规范

- `lib/api/{name}/` — 三文件：`http.dart` / `parse.dart` / `export.dart`
- `tool/` — API 探针场景注册（`tool/api_scenarios.dart`）与执行（`tool/api_probe_test.dart`），真实请求验证
- `lib/services/` — 无状态业务逻辑；命名混用两类：`{domain}_service.dart`（如 `api_service.dart`）与领域名式 `{domain}.dart`（如 `mt_image_hosting.dart`、`clipboard_paste.dart`）
- `lib/pages/{feature}/` — 页面 + 子组件拆分，>500 行时拆分
- `lib/widgets/` — 功能独立的可复用组件

### 大文件拆分（>500 行）

按两种既有范式拆分，**只搬代码不改逻辑/文案**，拆完必须 `flutter analyze lib` + `flutter test` 双绿：

| 场景 | 范式 | 范例 |
|---|---|---|
| 页面 `State` 的状态逻辑 / 构建方法 | `part` + `extension on _XxxState`：宿主声明 `part 'xxx.dart';`，part 首行 `part of 'xxx.dart';` 并定义扩展。扩展可访问该类私有成员，类体内可无前缀直接调用扩展方法 | `pages/thread/thread_view_actions.dart`、`pages/editor/editor_page_layout.dart`、`core/parser/bbcode2html_convert.dart` |
| 可独立的展示型组件 / 对话框 | 独立 Widget 文件（公开类 + 参数回调） | `pages/thread/thread_favorite_note_dialog.dart` |

拆分注意：
- part 文件不能有自己的 `import`/`part` 声明，依赖 import 必须留在宿主文件。
- 扩展内不能调用 `State` 受保护的 `setState`，用宿主预留的 `_setState`（自带 `mounted` 判断）桥接；`build` 是接口成员，不能整体搬进扩展，宿主保留一行薄覆写。
- 扩展不能有 `static` 成员：`static` 方法/字段留在类里（扩展内用 `类名.xxx` 限定），或把仅局部使用的 `static final` 改为 part 文件里的顶层变量。
- 匿名扩展的成员对 import 方不可见；搬移对外公开方法（如 `BBCode2Html.convert`）时扩展必须具名。

## 日志规范

- 全局：`AppLogger.{d/i/w/e}(tag, message)`，**禁止** `print` / `debugPrint`
- 标签约定：`DIO` / `PARSE` / `PAGE` / `CACHE`
- 开关：`AppLogger.enabled = false` 全局关闭

## 通用 UI 规范

- 对话框：`maxWidth: 360~420`，必须有关闭按钮，`barrierDismissible: true`
- 错误页：`PageErrorWidget` 统一使用，不弹 SnackBar，提供重试按钮
- 站点切换类界面不显示关闭按钮（用户必须选一个站点）
- 点赞/收藏等无参数操作：直接 GET，无对话框
- **内容页顶部操作统一走 `PageActions`**（`widgets/common/page_actions.dart`）：刷新按钮 + 「在浏览器中打开 / 复制链接 / 搜索」菜单，**不要**在页面里另写裸 `IconButton(Icons.refresh)`（会造成"有的页有刷新、有的页没有，且浏览器打开入口时有时无"）。参数：
  - `url`：该页对应的**站内完整地址**（`SiteStore.instance.baseUrl` + 该页 API 的请求路径，去掉 `page` / `inajax` / `ajaxdata` 等参数）
  - `onRefresh` / `loading`：刷新回调与加载态（页面能自行 `setState` 刷新时传 `loading`；由 `ThreadListController` 驱动、页面不随其重建的页面不传）
  - `copyLabel`：复制链接的提示文案（如「复制版块链接」）
  - 无对应站内 URL 的页面（顶层 Tab、设置页、本地浏览记录、编辑器等）不适用

## 图片加载规范

### 禁止项

- **禁止** `Image.network()` — 无磁盘缓存、不支持自定义请求头
- **禁止**不指定 `cacheManager` 的 `CachedNetworkImage` — 框架默认缓存不带 Referer

### 管理器选择

| 场景 | cacheManager |
|------|--------------|
| 帖子图片、封面图、画廊、图床缩略图 | `imageCacheManager` |
| 用户头像 | `avatarCacheManager` |
| 表情图片 | `emojiCacheManager`（或走 `StaggeredEmojiImage` 组件） |

> 初始化（`main.dart` 的 `initCacheManagers(...)`）、Referer 策略与完整规范见 `docs/01-概述与架构.md` →「图片缓存规范」和「Referer 模拟策略」。

## 页面接管开关（App 页面 ↔ 内置浏览器）

App 自研了一批页面（帖子详情/用户主页/搜索/我的…），个别可能不合用户口味。设置 →「页面接管」可**逐页**关闭：**默认全部开启 = 走 App 页面；关闭某项 = 该页无论从哪进入都改用内置浏览器**（全局，不按站点隔离）。

- **唯一生效点**：GoRouter 顶层 `redirect`（`lib/config/router.dart` → `appPageRedirect`）。所有导航（链接点击、帖子卡片、头像、入口 ListTile、系统入站链接、深链）都要过 redirect，因此**天然全入口覆盖**，不要在调用点再埋判断。
- **实现与 id 注册表**：`lib/core/app/app_page_gate.dart`。

新增一个可被接管的页面，两步：

1. `app_page_gate.dart` 的 `appPages` 加一项（`id` 稳定、勿改，用于持久化）；
2. 在 `featureIdOf`（App 路径 → id）与 `siteUrlFor`（App 路径 → 站内 URL）各加一个分支。

注意：

- 开关状态是**模块级变量**（不是 Provider 字段），由 `SettingsProvider.load()` / `setAppPageEnabled()` 写入 —— redirect 回调没有 context，且启动早期就要生效（同 `api_service.dart` 的 `_simulateBrowserHeaders` 做法）。
- `siteUrlFor` 算不出地址时**保持走 App**（如顶层 `/forum` 无 fid、参数缺失），不要硬凑一个不对应的 URL。
- 底部 Tab（首页/导读/消息）、设置、浏览记录等**没有"单页 URL"的页面不纳入**（关掉会变成"点 Tab 跳浏览器"）。
- **只拦"内容页"，不拦"入口/容器页"**：`/search` 是搜索中心（站内搜索/Bing/打开链接/找用户/历史多个功能），纳入开关会把其它功能一起废掉——只有 `/search/result` 才是"站内搜索结果"页。新增开关时先问一句：这一页是不是还承担了别的入口职责？
- **PC 专属页回退时用 PC UA**：在线用户 / 小黑屋在 Discuz 移动模板通常没有实现，回退时自动带 `&ua=pc`（浏览器以「桌面模式」打开，可在浏览器菜单切回）。名单见 `app_page_gate.dart` 的 `_desktopUaPageIds`；`BrowserPage.desktopUa` 由路由 `?ua=pc` 注入。
- **全局逃生阀 `browserOnlyMode`**（设置 → 页面接管 →「全部改用内置浏览器」）：开启后**除 `/browser` 与 `/settings*` 外所有路由都改走内置浏览器**，算不出站内地址的页（Tab 等）退化到站点首页。用途：App 侧反复被人机验证/防盗链卡住时一键降级为浏览器。
- **逃生阀的三道"改得回来"保险**（缺一即可能把用户锁死）：① redirect 放行 `/settings*`；② 内置浏览器右上角菜单常驻「设置」入口（顶栏不再单独放设置按钮，但菜单始终可点）；③ 左上角「退出浏览器」按钮在无路可退时改为去设置（避免 pop 掉唯一路由）。改这块务必同步守住这三处。左上角退出按钮与菜单里的「退出浏览器」共用 `_closeBrowser()`，行为一致。
- 回归测试：`test/app_page_gate_test.dart`（含 redirect 决策与 id/URL 互查）。
