# 鸿蒙 HAP 从零部署与构建

> 适用：**别人克隆本仓库后，如何把自己的机器配起来、打出鸿蒙 HAP**。
> 本文是「部署视角」；环境原理、依赖 fork 明细、踩坑清单见 [01-环境与构建.md](./01-环境与构建.md)。
>
> 文中 `<...>` 都是占位符，按你自己机器的实际路径替换。

## 0. 前置条件

| 项 | 要求 | 备注 |
|---|---|---|
| 操作系统 | Windows 10/11 x64 | 本文命令为 PowerShell |
| DevEco Studio | 6.0+（实测 26.0） | 含 HarmonyOS SDK（API 26 实测可用） |
| Flutter-OH SDK | `oh-3.44.9-dev` | 鸿蒙专用分支，**不是**官方 Flutter |
| fvm | 4.x | 用于管理两套 Flutter SDK |
| JDK | 17 | DevEco 通常自带 jbr |
| 磁盘 | 约 15 GB | 两套 SDK + 引擎产物 + pub/git 缓存 |

> ⚠️ 鸿蒙**不能**用官方 Flutter 构建：OH 侧插件引用了 `TargetPlatform.ohos` 等官方框架不存在的枚举。

## 1. 安装 DevEco Studio 与 HarmonyOS SDK

1. 从华为开发者官网下载 DevEco Studio 并安装（默认 `C:\Program Files\Huawei\DevEco Studio`）。
2. 首次启动按向导登录华为开发者账号，并在 SDK Manager 中安装 **HarmonyOS SDK**（实测 API 26）。
3. 确认以下路径存在：

```powershell
$DevEco = 'C:\Program Files\Huawei\DevEco Studio'
Test-Path "$DevEco\tools\ohpm\bin\ohpm.bat"      # ohpm 包管理
Test-Path "$DevEco\tools\hvigor\bin\hvigorw.bat" # hvigor 构建
Test-Path "$DevEco\sdk\default\openharmony"       # HarmonyOS SDK
```

## 2. 安装 Flutter-OH SDK

```powershell
fvm fork add flutter_ohos https://gitcode.com/CPF-Flutter/flutter_flutter.git
fvm install flutter_ohos/oh-3.44.9-dev
fvm list      # 确认已安装；记下它的实际路径，通常为 %USERPROFILE%\fvm\versions\flutter_ohos\oh-3.44.9-dev
```

选 `oh-3.44.9-dev` 的原因：`pubspec.yaml` 要求 `sdk: ^3.12.2`（Dart ≥ 3.12.2），
它配套 **Dart 3.12.2**；而更"稳定"的 `oh-3.35.7`（Dart 3.9.2）**不满足**该约束。

## 3. 配置环境变量（每个新终端都要设）

```powershell
$DevEco = 'C:\Program Files\Huawei\DevEco Studio'
$env:DEVECO_SDK_HOME = "$DevEco\sdk"
$env:PATH = "$DevEco\tools\ohpm\bin;$DevEco\tools\hvigor\bin;$DevEco\tools\node;$env:DEVECO_SDK_HOME\default\openharmony\toolchains;$env:PATH"
# 鸿蒙引擎产物托管在华为云 OBS；不设会去 Google Storage 下载而失败
$env:FLUTTER_OHOS_STORAGE_BASE_URL = 'https://flutter-ohos.obs.cn-south-1.myhuaweicloud.com'
# 可选：消除 flutter doctor 的 git 仓库警告
$env:FLUTTER_GIT_URL = 'https://gitcode.com/CPF-Flutter/flutter_flutter.git'

# 自检：应看到 [√] HarmonyOS toolchain
& '<Flutter-OH SDK 路径>\bin\flutter.bat' doctor -v
```

## 4. 补齐本机专属文件（这些不进仓库）

仓库里 `ohos/` 是完整的工程，但有几处"每台机器都不同"的内容被有意排除，需要你自己生成：

| 文件 | 为什么不在仓库 | 怎么补 |
|---|---|---|
| `ohos/local.properties` | 含 SDK 绝对路径 | **仓库已提供 `ohos/local.properties.example`，重命名即可**；跑一次 `flutter build hap` 也会自动生成 |
| `ohos/build-profile.json5` 的 `signingConfigs` | 含证书路径与加密口令 | 保持为空数组，用 DevEco 自动签名（见第 6 节） |
| `ohos/node_modules`、`ohos/oh_modules`、`**/build`、`ohos/.hvigor` | 依赖与构建产物 | 构建时自动生成 |
| `~/.ohos/config/*` | 证书本体存在用户目录 | DevEco 自动生成 |
| `android/key.properties` | 含签名口令 | **仓库已提供 `android/key.properties.example`，重命名即可**（可选，不配则回退 debug 签名） |
| `android/app/key.jks` | 二进制密钥库，无法提供示例 | 用 `keytool` 自己生成，见 `android/key.properties.example` 内注释 |
| `mtbbs_release.json` | `scripts/version.ps1` 生成的构建元数据 | 跑该脚本自动生成 |
| `.metadata` | 用 OH SDK 跑 `flutter create --platforms ohos .` 会把它**重写**成 fork 的 revision / `[user-branch]` channel，并丢掉 android/ios 等平台迁移条目 | 提交前 `git checkout -- .metadata` 还原；实测鸿蒙构建**不依赖**它的 ohos 条目，保持官方版本即可 |

> 判断标准：**只要某段内容包含绝对路径、账号、密钥、口令，或者可以重新生成，就不该提交。**

## 5. 启用鸿蒙依赖覆盖

pub.dev 上的插件没有 ohos 实现，需要临时切到 OpenHarmony 社区 fork：

```powershell
# 模板文件常驻仓库但本身不生效，复制成生效文件
Copy-Item ohos\pubspec_overrides.ohos.yaml pubspec_overrides.yaml -Force

& '<Flutter-OH SDK 路径>\bin\flutter.bat' pub get
```

自检（必须输出 4 个插件，否则构建会报 `Cannot read properties of undefined (reading 'filter')`）：

```powershell
(Get-Content .flutter-plugins-dependencies -Raw | ConvertFrom-Json).plugins.ohos.name
# file_picker / flutter_inappwebview_ohos / path_provider_ohos / url_launcher_ohos
```

> ⚠️ **`pubspec_overrides.yaml` 绝不能常驻**：只要它存在，Android / Windows 就编不过
> （OH fork 硬编码 `TargetPlatform.ohos`）。用完必须按第 8 节恢复。

## 6. 配置签名

### 方式一：DevEco 自动签名（本地调试用）

1. DevEco Studio → **File → Open** → 选择本仓库的 `ohos` 目录（**不是**仓库根目录）
2. 右上角登录华为开发者账号
3. **File → Project Structure → Signing Configs** → 勾选 **Automatically generate signature** → Apply

DevEco 会把证书路径与口令写进 `ohos/build-profile.json5` 的 `signingConfigs`。
**提交前务必清空该数组**（本仓库默认即为空，见第 9 节）。

### 方式二：只出无签名包（侧载分发用）

不配置签名，构建时加 `--no-codesign`，产物由使用者自行签名安装。仓库默认走这条路。

## 7. 构建 HAP

```powershell
$foh = '<Flutter-OH SDK 路径>\bin\flutter.bat'

# 通用包（真机 arm64 + 模拟器 x64 合一），无签名，体积最小
& $foh build hap --release --target-platform ohos-arm64,ohos-x64 --no-codesign

# 只出单架构（体积更小）
& $foh build hap --release --target-platform ohos-arm64 --no-codesign

# 模拟器调试包
& $foh build hap --debug --target-platform ohos-x64
```

- `--target-platform` 支持 **逗号分隔多架构**（`ohos-arm64` / `ohos-arm` / `ohos-x64`），一次构建产出一个包
- 体积参考：debug x64 约 152 MB；release arm64 约 33 MB；release 通用包约 65 MB
- 产物：`build/ohos/hap/entry-default-{unsigned,signed}.hap`

## 8. 安装

```powershell
$hdc = "$env:DEVECO_SDK_HOME\default\openharmony\toolchains\hdc.exe"
& $hdc list targets
& $hdc install -r build\ohos\hap\entry-default-signed.hap   # 未签名包无法安装
```

## 9. 收尾：恢复主线（必做）

```powershell
Remove-Item pubspec_overrides.yaml -Force
flutter pub get          # 用官方 Flutter 重新解析

# 若上一步崩在符号链接错误，Windows 侧生成文件可能残留鸿蒙痕迹，还原即可
git checkout -- pubspec.lock windows/flutter/generated_plugin_registrant.cc windows/flutter/generated_plugins.cmake

# 自检：应为 0 条 + 无 pubspec.lock / generated_* 改动
Select-String -Path pubspec.lock -Pattern 'gitcode'
git status --short
```

## 10. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `TargetPlatform.ohos` / `initOhosView` 找不到 | 用了官方 Flutter SDK 构建鸿蒙；改用 Flutter-OH SDK |
| `hvigor ERROR ... undefined (reading 'filter')` | `.flutter-plugins-dependencies` 缺 `ohos` 段（工作区处于主线态）；按第 5 节切回鸿蒙态 |
| `Cannot create link ... .plugin_symlinks\file_picker` | 环境竞态，**无害**；原样重跑一次 |
| `EPERM ... mkdir 'C:\Users\<你>\.hvigor\...'` | hvigor 需要写用户目录，别在受限沙箱里构建 |
| 构建后 Android/Windows 编不过 | `pubspec_overrides.yaml` 还在；按第 9 节恢复 |
| Android 报 `Member not found: 'ohos'` | 同上 |
| 签名相关报错 | 未配置签名且没加 `--no-codesign`；二选一 |
| 首次 `--release` 构建失败且无有效日志 | 实测偶发，原样重跑即成功 |

更多细节（依赖 fork 的版本差异、`web` 冲突的处理、`multiAppMode` 取值等）见
[01-环境与构建.md](./01-环境与构建.md)。
