# 站内搜索

> 适用：维护/扩展 `search.php` 站内搜索（原生结果页、模板解析、翻页、探针）时阅读。按需。

## 一句话

Discuz 搜索无 JSON API：**纯 GET `search.php?mod=forum`**（无 formhash、无 POST、**不带 `&inajax=1`**）→ 跟随 302 拿 `searchid` → 解析完整 HTML；结果模板随「浏览模式」UA 切换（移动=克米卡片 / 桌面=标准 Discuz），两套都由解析器工厂兜住。

## 请求流程

| 步骤 | 请求 | 要点 |
|---|---|---|
| 搜索 | `GET /search.php?mod=forum&srchtxt={kw}&searchsubmit=yes` | `submitcheck('searchsubmit', 1)` 的 `$allowget=1` **跳过 formhash 校验**，无需登录令牌（见 Discuz 源码 `helper_form::submitcheck`）；Dio 默认跟随 302 |
| 拿 searchid | 302 → `/search.php?mod=forum&searchid={sid}&orderby=lastpost&ascdesc=desc&searchsubmit=yes&kw={kw}` | `searchid` 只出现在重定向后的最终 URL（`response.realUri`），空结果页 body 里没有分页链接可兜底 |
| 翻页 | `GET /search.php?mod=forum&searchid={sid}&orderby=lastpost&ascdesc=desc&searchsubmit=yes&page={n}` | Discuz 靠 `common_searchindex` 表的 `searchid` 翻页；**不带 searchid 的 page 参数无效** |

- UA 用 `SiteStore.instance.userAgent`（受设置「浏览模式」控制），与导读/版块一致。
- 移动 UA 会被服务端追加 `&mobile=2`，无副作用。
- 越界页返回 0 条（可"页空即止"，但两套模板都有服务端分页栏，优先用它）。

## 两套模板 DOM 对照

| | 桌面版（标准 Discuz） | 移动版（克米） |
|---|---|---|
| 列表项 | `#threadlist li.pbw`（**不是**版块的 `tbody[id^=normalthread_]`） | `li.forumlist_li.comiis_znalist` |
| 标题/链接 | `h3 a`（`tid=` 或 `thread-{tid}-1-1.html`） | `.mmlist_li_box h2 a` |
| 摘要 | `li` 内非 `xg1`、无链接的 `<p>` | `.list_body` |
| 回复/查看 | `p.xg1`「N 个回复 - M 次查看」 | `.comiis_xznalist_bottom li` = [赞, 评论, 浏览] |
| 作者/版块 | 元信息 `<p>` 内 `space-uid-*.html` / `forum-*-1.html` | `.top_user` / `.comiis_xznalist_bk a` |
| 分页 | `.pgs .pg`（`strong`=当前，`span[title="共 N 页"]`=总页） | `.comiis_multi_box .pg`（同上） |
| 每页 | 20 | 10 |

> 测试站 `discuz.qcxs.top` 是**旧版克米**：底部容器是 `.comiis_znalist_bottom`、版块在时间行、统计序为 [阅读,评论]，与 MT 有细差。**以 MT 论坛为准**，测试站只用于流程验证。

## 解析策略（复用优先）

- 移动端：命中现有 `ComiisCardParser`（与导读/版块卡片同构），零改动。
- 桌面端：`DiscuzSearchParser`（特征 `#threadlist li.pbw`）——已注册进 `ThreadListParserFactory`（工厂本就为"新增模板"设计）。
- 分页：复用 `extractPagination`（`.pg strong` + `span[title="共 N 页"]`，两套模板通吃）。
- 错误/登录/拦截页：复用 `prepareDoc`（`loginRequired` 广播见 `docs/02`）。

## API 与探针

- 三文件：`lib/api/forum/search/{http,parse,export}.dart`；`export.searchThreads` 额外注入 `searchId`。
- 探针（`docs/10`）：
  ```
  flutter test tool/api_probe_test.dart --dart-define=cmd=search.list --dart-define=kw=逆向 --dart-define=page=1
  ```
  翻页追加 `--dart-define=searchid=<上次返回>`；测试站加 `--dart-define=baseUrl=http://discuz.qcxs.top`；MT 需登录态 `--dart-define=account=<账号>`，命中反爬时补 `--dart-define=cookie=acw_sc__v2=<值>`。

## UI 与路由

- 结果页 `lib/pages/search/search_result_page.dart`（路由 `/search/result?kw=`）：AppBar 内嵌搜索框 + 复用 `ThreadGrid`；`searchid` 存于 `ThreadListController.fetchFn` 闭包，首帧写入、翻页复用，换词时清空；触发限流时切换为「搜索过于频繁」+ 倒计时禁用重试。
- **关键词高亮**：`HighlightedText`（`widgets/common/highlighted_text.dart`）按关键词切 `TextSpan`，在标题/摘要里强调（颜色取 `cs.searchHighlightColor`）。**不复用服务端高亮标记**——parse 层已按数据层边界把 `<strong><font>` 剥成纯文本，且标题/摘要本身是纯字符串模型；客户端按已知关键词做大小写不敏感的子串匹配更简单可靠。`ThreadCard` / `ThreadGrid` 透传 `highlight` 参数（默认空=不启用，不影响导读/版块）。
- AppBar 菜单复用 `PageActions`（与帖子页同款）：「在浏览器中打开」用 `searchPageUrl(searchId:…)` 直接打开**该次搜索的结果页**（走 `searchid`，不新建搜索、不触发频率限制；未拿到 searchid 时退化为关键词 URL），另有「复制搜索链接」。
- 入口：`/search` 页的「站内搜索」由"推浏览器"改为 push 结果页（`search_page.dart`）。同页的「查看用户」建议用**宽松判定**（只排除含空白、过长、像链接的输入），**不套用注册用的 `UsernameValidator`**——站点里更短/更长、或手机号这类纯数字用户名都真实存在，按注册规则过滤会让它们"搜不到"；数字输入先按 UID 查、查不到再按用户名查一次（`_resolveUid`）。

## 边界与注意

| 场景 | 表现 / 处理 |
|---|---|
| 游客搜索 | 站点可禁游客搜索：移动端 302 到 comiis 登录页（title「登录」，无 `input[name=loginsubmit]`），PC 端消息页（title「提示信息」）——`search/parse` 兜底识别为 `loginRequired`（`prepareDoc` 覆盖不到这两种） |
| 频率限制 | Discuz 两条：`search_ctrl`（同 IP/UID `searchctrl` 秒内再搜）与 `search_toomany`（每分钟 `maxspm` 次）。**实测 MT `searchctrl=10` 秒，任意两次新搜索间隔 <10s 即拒**（无结果也占配额）。触发时服务端返回消息页，`prepareDoc`（`comiis_password_top`）/搜索兜底捕获；结果页识别文案中的秒数，展示「搜索过于频繁」并**倒计时禁用重试**。**翻页与下拉刷新复用 `searchid`，不新建搜索、不受限**（只有"换新词发起新搜索"才计数） |
| `searchid` 过期 | 服务端返回 `search_id_invalid`（「抱歉，您指定的搜索不存在或已过期」）→ 走通用错误提示，需用户手动重搜 |
| 消息页区分 | 游客无权搜索 = 302 登录页（title「登录」）；限流/无权限 = 消息页（`comiis_password_top`） |
| 人机验证/防火墙 | 现有 `looksLikeInterstitialPage` + 本地自解 + Dio 重放（见 `docs/20`） |
| `_mobile` cookie 压 UA | 走同一 Dio，`ApiService._dropBrowseModeCookie` 自动生效（见 `docs/07 #72`） |
