# 留言板

> 适用：用户留言板（`home.php?mod=space&uid={uid}&do=wall`）的只读解析与发布/编辑/回复/删除写操作，以及 App 页面 `/user/:uid/wall`。按需。

## 1. 定位与模板

Discuz 个人空间的「留言板」tab（**仅 PC 模板**：克米移动模板无此 tab，解析依赖标准 PC 的 `#comment_ul > dl[id^=comment_]`），因此请求显式覆盖 `User-Agent` 为 PC（见 `lib/api/home/wall/http.dart`），不跟随站点「浏览模式」。

- 列表页：`GET home.php?mod=space[&uid=X]&do=wall[&page=N]`（`uid` 空 = 自己；**每页 20 条**，`.pg` 分页）
- 单条 DOM：`dd.m.avt`（头像）→ `dt`（操作链接 + `a#author_{cid}` + `span.xg1.xw0` 时间）→ `dd#comment_{cid}`（正文，回复时含 `.quote > blockquote` 引用块）

## 2. 写操作协议（四个，全部实测）

| 操作 | 请求（均 `inajax=1` 返回 XML） | 关键字段 |
|---|---|---|
| 发布 | `POST home.php?mod=spacecp&ac=comment` | `id={uid}` `idtype=uid` `commentsubmit=true` `quickcomment=true` `handlekey=qcwall_{uid}` `message` `formhash` |
| 回复 | `POST home.php?mod=spacecp&ac=comment` | 同发布 + `cid={cid}`、`handlekey=replycommenthk_{cid}`，**去 `quickcomment`** |
| 编辑 | `POST home.php?mod=spacecp&ac=comment&op=edit&cid={cid}` | `editsubmit=true` `handlekey=editcommenthk_{cid}` `message` `formhash` |
| 删除 | `POST home.php?mod=spacecp&ac=comment&op=delete&cid={cid}` | `deletesubmit=true` `handlekey=delcommenthk_{cid}` `formhash` |

- **`handlekey` 是可按 `uid`/`cid` 本地推导的字面串**（服务端只做字面比对，实测推导全通过），无需从 DOM 抓。
- **`formhash` 一页共用一个**：四种操作都取自留言板页任意 `input[name=formhash]`，不必为编辑/删除单拉表单页。
- **响应**：成功 `succeedhandle_xxx(url,'操作成功 ',{'cid':'N'})`；失败 `errorhandle_xxx('抱歉…',{'waittime':'N'})` —— 交给 `parseSubmitResponse`（见 `core/parser/xml_helper.dart`）。
- **限流**：发布/回复有 ~7–10s 间隔（`errorhandle` 带 `waittime`）；编辑/删除不受限。
- **Content-Type 必须显式** `application/x-www-form-urlencoded`（同 docs/12）。

## 3. 内容渲染：受限白名单，不是完整帖子 BBCode

服务端对留言做 `discuzcode` 的**受限**渲染（实测）：`[b][i][u][quote][img]` 与裸 URL 会渲染成 HTML；`[color][size][font][url=…]` 与表情 `[呵呵]` **原样输出**。因此展示侧把 `dd#comment_{cid}` 的 HTML 经 `Html2BBCode` 回退为 BBCode（引用块单独拆成 `quotedUser/quotedText`），再交统一渲染管线（见 docs/02 数据层↔渲染层边界）。

## 4. 权限差异（按实际渲染的操作链接判定）

| 视角 | 编辑 | 删除 | 回复 |
|---|---|---|---|
| 自己的墙 · 自己的留言 | ✓ | ✓ | ✗ |
| 自己的墙 · 他人的留言 | ✗ | ✓（墙主） | ✓ |
| 他人的墙 · 自己的留言 | ✓ | ✓（作者） | ✗ |
| 他人的墙 · 他人的留言 | ✗ | ✗ | ✗ |

parse 层输出 `canEdit/canDelete/canReply`，页面据此渲染，**不写死权限**。

## 5. 坑

1. **必须带 `X-Requested-With: XMLHttpRequest`** —— 裸 POST 会被阿里云 ESA WAF 拦成 `acw_sc__v2` 挑战页（见 docs/07 #80）。App 的 `ApiService` 默认已带，无需额外处理。
2. **「回复」是跨墙投递**：回复内容会发布到**被引留言作者的留言板**（实测提示"已经回复到 {作者} 的留言板"），而非当前墙。页面回复按钮因此标注"将发布到 TA 的留言板"；App 内测试回复务必清理到对方墙上。
3. **`errorhandle_` 带函数后缀**（`errorhandle_qcwall_{uid}(…)`），而 `parseSubmitResponse` 的错误正则只匹配 `errorhandle_('…'`；当前靠"含『抱歉』"的文本兜底仍判失败。若要让错误分支更稳，可把该正则与成功分支对齐为 `errorhandle_(?:\w+)?\('`（本次未改，避免波及既有写操作）。
4. 删除为**两步的表单**（GET 出确认表单），但**直接 POST `op=delete` + `deletesubmit=true` 即可**，无需先 GET。

## 6. App 落地

| 层 | 文件 |
|---|---|
| API 三文件 | `lib/api/home/wall/{http,parse,export}.dart` |
| 模型 | `lib/models/wall_comment.dart`（并入 `models.dart` barrel） |
| 页面 | `lib/pages/user/wall_page.dart`，路由 `/user/:uid/wall`（`uid=self` = 自己）；发布/编辑用与帖子页同源的 `MiniEditorBar`（撤销/重做、工具栏、表情、MT 图床、预览） |
| 编辑器上下文 | `MiniToolbarContext.wall`：默认 undo/redo/bold/link/emoji/mtImage，不支持 `image`/`attach`/`quickReply`；老配置由 `syncToolbarWithDefaults` 自动补上 `wall`（见 docs/06） |
| 字数上限 | 设置项「站点字数限制」（`SettingsProvider.postMaxLength`，默认 65535，未配置按此计），编辑器与留言板共用 |
| 入口 | 用户主页头部「留言板」按钮（`pages/user/user_profile_sections_extra.dart`） |
| URL 映射 | `core/utils/url_router.dart` 的 `mod=space` 分支（`do=wall`，须排在 `uid→/user/{uid}` 之前） |
| 探针 | `wall.list` / `wall.post`（`cid` 空=发布，非空=回复）/ `wall.edit` / `wall.delete` |

```bash
# 只读

flutter test tool/api_probe_test.dart --dart-define=cmd=wall.post --dart-define=uid=88062 --dart-define=message=测试 --dart-define=account=青春向上 --dart-define=log=off
```
