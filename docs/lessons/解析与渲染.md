## 解析相关

1. **Discuz inajax 的 content-type** — 只有少量页面返回 XML，多数返回 HTML（"discuz_uid" 标记），还有 JSON 或纯文本。**不要假设 content-type**，以响应内容为准。
2. **优先 DOM 解析**（`xml_helper.dart`）—— 即使 HTML 不规范也优先 DOM，正则只用于 DOM 无法处理的场景（如行内表情、签名混合内容）。
3. **`parseSubmitResponse` 统一入口** — 所有表单提交的响应解析走此函数，它处理 `succeed`、`alert`、`location` 等 Discuz 通用返回格式。

81. **克米移动版个人空间「资料行」是"值在前、标签在后"，且标签的包裹层级逐行不同——按 `span` 向下找值必然落空** — 症状：移动端个人空间**个人签名不显示**（文本/链接/图片签名全丢），而用户ID、自定头衔等正常。**根因**：`.comiis_space_profile li` 的真实结构是「值元素（`.profile_r`/`.profile_rs`）在前，标签 `<span>` 在后」，且标签外面套的层级随行变化——用户ID 是 `li > span` 直挂，自定头衔把值和标签一起包进 `a.profile_a`，个人签名则把标签包进 `strong > font`。旧代码 `span.parent?.querySelector('.profile_r,.profile_rs')` 只查"标签自己的包裹元素"，前两种碰巧命中（`a` 里含值、`li` 里含值），签名行的 `font` 里什么都没有 → 返回 null → 签名丢失。**修法**：从标签**向上**找到所在 `<li>`，再在行内取值（`_comiisRowValue`，见 `lib/api/home/space/parse.dart`）。**关键辨析——签名尾部的"空样式标签对"是用户有意为之，不是模板注入，别当垃圾清理**：喵喵猫签名的原始 HTML 是 `<div class="profile_r…"><img …><strong><font color="white"></div>`——`[img]…[/img]` 之后跟了**未闭合**的 `[b][color=white]`（签名"染页"手法：把开标签挂在值末尾，让页面后续内容继承白色加粗，浏览器里连"个人签名"标签都被染色）。判定有两条硬证据：① 原始响应里这对标签紧贴 `</div>`、**没有闭合标签**，是 `$sightml` 原样输出，模板不会这么写；② 对照另一用户（uid=88062）同一行是干净的 `<div class="profile_r profile_face f_c">年少不知号贵，猥琐升级，勿浪！</div><span>个人签名</span>`——若模板会注入，人人都有。经 HTML 解析器在 `</div>` 处补全后，DOM 里表现为空的 `<strong><font color="white"></font></strong>`，转 BBCode 得 `[b][color=white][/color][/b]`，**要原样保留**（它无害，删掉即篡改用户内容）。另注：Discuz 自己的 `html2bbcode()` 也啃不动未闭合标签——`recursion()` 找不到 `</tag>` 就 `break` 原样留着（`function_editor.php`），所以本就没有"标准回译"，以 DOM 为准即可。**PC 端另走一条路、本就正常**：标准 Discuz 的签名行是 `.u_profile` 下的 `<li><em class="xg1">个人签名&nbsp;&nbsp;</em><table><tr><td>$sightml</td></tr></table></li>`（`template/default/home/space_profile_body.htm`），`_parseSignature` 按 `ul>li`→`em`→`table td` 取值，与模板对得上（所以本 bug 只在移动分支）。且 `sightml` 是**保存时**由 `discuzcode()` 渲染入库的，PC/移动拿到的是**同一份** HTML，两端解析结果逐字一致——喵喵猫那对未闭合的染页标签在 PC 端同样存在。**验证**：`tool/api_probe_test.dart --dart-define=cmd=user.info --dart-define=username=喵喵猫` 实测返回 `signature: "[img]https://ftp.bmp.ovh/…gif[/img][b][color=white][/color][/b]"`（签名图 + 用户那对未闭合标签，都保留）。**另一处佐证**：Discuz 存签名时就把 BBCode 转成 HTML（`spacecp_profile.php` 用 `discuzcode(...)` 写入 `sightml`），编辑时再 `html2bbcode()` 转回——App 的 HTML→BBCode 方向与站点一致；且**移动模式**下 `[img]` 由 `parseimg` 渲染成 `<img width height src=… border=0 alt="">`（**没有** `class="zoom"`、也没有 `file=` 懒加载属性），所以取值只能靠 `src`。

83. **从链接兜底推断分页时必须排除正文/楼层区，否则帖子里的跨帖引用会把单页帖子算成多页** — 症状：某帖（`tid=174316`）在 App 里显示两页（实际只有一页），且评论区出现重复内容；换别的 tid 正常。**根因**：单页帖子 Discuz **不渲染** `.pg` 分页栏（`.pg` 只在 `totalpages > 1` 时输出），于是 `extractPagination` 落到兜底 `extractPaginationFromLinks`（`page_helper.dart`），该函数扫描**全文档**所有 `a[href*="page="] / a[href*="thread-"]` 取最大 `page`。这帖的**楼中引用**了另一个帖子（`.../forum.php?mod=viewthread&tid=174230&page=2&mobile=2`）——这个内容链接的 `page=2` 把 `maxPage` 抬到 2 → `totalPages=2`。随后 App 预加载第 2 页，而服务端把越界页**钳回第 1 页**（返回 `currentPage:1`，且 `page>1` 时解析层把楼主帖也当评论），于是 `_commentPages[1]` 被含楼主的那份数据覆盖 → 重复内容。**修法**：兜底扫描时跳过位于正文/楼层区内的链接（`_isInsidePostContent`：祖先含 `#postlist` 或 class 为 `t_f`/`t_fsz`）——这类链接是"用户内容"不是"分页栏"。**关键事实（省下次排查）**：克米/标准 Discuz 的 PC 帖子页，`.pg` **在**多页时才出现、且**不在** `#postlist` 内；单页时没有 `.pg`，此时正确结论就是 1 页。**验证**：`thread.detail --dart-define=tid=174316` → `totalPages:1`（修前 2）；`tid=174230`（真多页）仍为 `2`；回归测试 `test/page_pagination_test.dart`。

100. **52pojie 的 Markdown 插件没有 md 原文：只能把 Parsedown HTML 逆向还原成 Markdown，再复用 markdownToBbcode** — 症状：MD 帖整篇只剩第一个代码块，标题/表格/列表/引用全丢。**根因**：`Html2BBCode._matchByClass` 把整个 `div.parsedown-markdown` 当成一个代码块（`querySelector('code')`），而且 `div.parsedown-markdown-end_FLAG_xxx`（插件的隐藏结束标记）也被同一分支命中。**关键事实**：服务端 Parsedown 已把 `[md]…[/md]` 渲染成 HTML，页面里**没有**原始 Markdown（无注释、无 textarea、无 data-* 字段），所以"解析出 md 原文"不可行。**方案**：`lib/core/parser/html2markdown.dart` 把容器 DOM 还原成 Markdown（h1~h6→`#`…、`pre>code`→围栏、table→GFM 表、ul/ol→`- `/`1. `、blockquote→`> `、hr→`***`、a/img/strong/em/code→行内语法），再喂既有 `markdownToBbcode`（用**展示用模板**把标题放大到 32/24/18px；默认模板的 3/2/1 是为发帖回写设计的，在 App 里比正文还小）。**条件生效**：以「容器 class 存在」判定，不按站点硬编码 —— 其它站点没有该容器，行为完全不变；MT 等无插件站点照旧按纯文本。**踩坑**：① 跳过 `em.CopyMyCode`/`em.hideCode` 按钮与 `div.tip.aimg_tip` 浮层；② 代码一律取 `code.text`（扁平化 hljs `<span>`、`&nbsp;`→空格）；③ 正文需转义 Markdown 特殊字符 + 行首 `#`/`-`/`+`/`1.`，否则正文会被二次解析；④ `hr` 输出 `***` 而不是 `---`，否则 `markdownToBbcode` 的前置元数据（Front Matter）识别会把两个 `---` 之间的正文变成 `[free]`；⑤ `_format` 必须先把 `[code]` 块占位保护起来再做空白收敛，否则代码里的空行和缩进被吃掉（顺带修掉旧行为）。嵌套 `blockquote` 由 `markdownToBbcode` 折叠为单层 `[quote]`（App 的 `[quote]` 不支持嵌套）。验证：`test/html2markdown_test.dart`（结构还原 + 端到端 + 非 MD 站点不受影响）。

101. **「帖内标题」选择器不能命中正文区，否则 Markdown 帖标题会重复一次** — 症状：`thread-2123217` 正文开头出现两行标题：`[b]快手 VMP 分析与还原[/b]` 紧跟 `[size=5][b]快手 VMP 分析与还原[/b][/size]`。**根因**：`post_parser.dart` 用 `plc.querySelector('div.pcb h2')` 取「帖内标题」再前置 `[b]…[/b]`，注释写的是"不在 td.t_f 内"，但选择器是**后代匹配**——`td.t_f` 本身就在 `div.pcb` 里，于是 Markdown 插件输出的第一个 `<h2>`（作者写的 `## 帖标题`）既被当成帖内标题前置一次，又被 Html2Markdown 转成 `[size=5][b]` 输出一次。同理 `thread-717627` 的首个 h2「Markdown使用说明」也会被重复。**关键事实**：52pojie 的克米模板 `.pcb` 下只有 `div.t_fsz / div.cm / h3.psth / dl.rate`，**没有正文区外的 h2**（抽样 15 个帖子 `h2out` 全为空），这个前置逻辑本是为其它模板准备的。**修法**：`_findPostTitle` 遍历 `div.pcb h2`，用 `_isInsideContentCell`（祖先 class 为 `t_f`/`t_fsz`）跳过正文区，保留"正文区外 h2 仍作为帖内标题"的行为。**注意别直接复用** `page_helper.dart` 的 `_isInsidePostContent`：它把 `#postlist` 也算内容区，而「帖内标题」本来就在 `#postlist` 里，复用会让该功能整体失效。**验证**：`test/html2markdown_test.dart` 的 `parsePostFromTable - 帖内标题` 两条（正文 h2 只输出一次且以 `[size=5]` 开头；正文区外 h2 仍前置 `[b]`）。

103. **评分记录（`dl.rate`）跨模板有三个差异点：昵称链接、uid 形式、`p.ratc` 语义** — 症状：52pojie 的帖子评分记录在 App 里只剩表头（`吾爱币 +16 / 热心值 +14`），**一条用户记录都没有**，且汇总位置显示「查看全部评分」这种操作文案。**根因**（同一份 `parsePostFromTable`，两站 DOM 不同）：① 克米模板昵称是 `<a class="xg1">`，52pojie **没有 `xg1`**，且该单元格里**第一个 `<a>` 是头像链接（文本为空）**——`querySelector('a.xg1')` 返回 null，整行被跳过；② uid 链接克米是 `space-uid-123`，52pojie 是 `home.php?mod=space&uid=123`，`space-uid-(\d+)` 匹配不到；③ 克米 `p.ratc` 是纯文本汇总，52pojie 同一位置放的是「查看全部评分」链接，原逻辑直接取 `p.text` 当汇总。**修法**：新增 `_findRateUserNameLink`（`a.xg1` 有可见文本则优先，否则取单元格内第一个**带可见文本**的 `<a>`，避开头像）；uid 正则改为 `space.*?uid[=-](\d+)`（作者区本来就用这条）；`p.ratc` 内若含 `a[href*=viewratings]` 则丢弃其文案，改用表头（`参与人数 15`）作 `totalScore`。**注意**：两站的 `tbody.ratl_l` 都在、行结构（昵称/分数列/理由列）也一致，**不要怀疑行选择器**——症状是"整个表空了"，但根因只在姓名链接。验证：`test/html2markdown_test.dart` 的 `parsePostFromTable - 评分记录` 两条（52 真实结构 + 克米结构各一条）。

## BBCode 渲染架构（占位元素 + 自定义组件注入）

> 渲染器已在 2026-09 从 flutter_html 换成 flutter_widget_from_html（见下方
> #43-50）。本节只保留跨渲染器仍然成立的规则：占位元素机制现在只服务
> `[code]`；`[table]` 由转换层直接输出 `<table>`，交给渲染器原生渲染。

31. **一次转换 + 占位元素，根治"分段拆散容器"类 bug** — `[hide]内容[code]…[/code]内容[/hide]` 里 hide 失效、原样显示文本的根因：按 code/table 切段后各段独立渲染，hide/quote/free 等容器的开闭标签被拆到不同片段 → 配对失败 → 原样输出。**根治**：不再分段，`BBCode2Html` 一次转换，`[code]` 还原为占位元素 `<div data-code-index="N">`，渲染器的 `customWidgetBuilder` 原地替换为 `BbcodeCodeBlock`（`post_html_widget.dart`）。容器结构在单次转换中天然完整，任意嵌套安全。代码原文存 converter 公开字段 `codeBlocks`（索引即占位符编号），越界时返回空组件、不崩溃。
33. **非法 hex 颜色必须在转换层丢弃，不能让渲染器去兜底** — `[color=#FFYYTT]` 会原样进入 `<span style="color:#FFYYTT">`，渲染器拿到非法值可能直接抛异常，连累整段甚至整篇渲染失败。**规则**：`BBCode2Html._normalizeColor` 只放行 `#` 后 3/4/6/8 位 hex，非法返回空串、调用点省略 style。与 #30 是两件事：一个"值非法要丢"，一个"值合法但语义要纠正"。
34. **嵌套 BBCode 用栈式配对，不用非贪婪正则** — 非贪婪 `[\s\S]*?` 会被内层 `[/table]`/`[/td]`/`[/tr]` 截断，导致 table 套 table、tr 内嵌 table 解析错位。用 `outerBlocks(input, tag)`（计数配对最外层）：`RegExp('\\[/?$tag\\]', caseSensitive: false)` 遍历，开标签 depth++、闭标签 depth--，depth 归零时产出 `(start, end)`。**Dart 陷阱**：必须用非原始字符串 `'\\[/?$tag\\]'`——`r'\[/?$tag\]'` 会把 `$tag` 当字面量（不插值）；另 `RegExp.firstMatch` 无 start 参数，需要偏移量时用 `substring(match.end)` 切片。
42. **编辑器附件链路：attachimg/attach 在编辑器侧转成 appdata，渲染层不可知** — 编辑器插入的是 Discuz 原生标签 `[attachimg]aid[/attachimg]` / `[attach]aid[/attach]`（正文按原样 POST，交给 Discuz 服务器渲染；同时提取 aid 绑定表单 `attachnew`）。**预览前**由 `_preparePreviewBbcode`（`editor_page.dart`）把二者替换为 `[appdata]{"type":"image_attach"|"attach", …}[/appdata]`，数据来自 `_aidToSrc` / `_aidToAttachment`（在页面抓取、快照恢复、上传成功时填充）；渲染层 `BBCode2Html` 只认 `[appdata]`，对 attachimg/attach 没有规则。**数据缺失时保留原标签是有意设计**：用户看到 `[attachimg]123[/attachimg]` 原文即知 aid 插错了，不要改成占位 appdata（那会掩盖错误 id）。

## 渲染引擎迁移：flutter_html → flutter_widget_from_html（2026-09）

43. **块级 / 内联由 `customWidgetBuilder` 的返回值决定，这是"表情内联 + 图片块级"共存的正解** — 返回 `InlineCustomWidget` → 占位符进入文字行内（`toPlainText()` 里表现为 `￼`）；返回普通 Widget → 独占一行的块级元素。同一份 `<img>` 用 `data-type="emoji"` 区分即可走两条路径，不再需要靠类型白名单和"有没有显式尺寸"去猜。判定实现在 `core_build_tree.dart`（`customWidget is InlineCustomWidget` 分支）。

44. **链接内图片的点击可以冒泡，因此图片组件绝不能挂 `onTap`** — 渲染器对 inline A 标签会把它内部的**块级**子元素逐个 `wrapWith(buildGestureDetector)`（`internal/ops/tag_a.dart`），把链接手势下沉到图片上。所以帖子图片只挂 `onLongPress`（长按菜单），点击就会自然冒泡到外层 `[url]`。挂了 `onTap` 反而会抢走点击，"点击图片跳链接"和"点击图片看大图"不能同时要。

45. **注入到表格单元格的块级组件必须容忍无限宽约束** — 表格列总宽超过可用宽时，渲染器会套一层横向滚动，测量单元格时下发 `w=Infinity`。此时 `Container(width: double.infinity)`、`Spacer`、`MainAxisSize.max` 都会抛 `BoxConstraints forces an infinite width`，**并中断整张表甚至整篇帖子的渲染**。`BbcodeCodeBlock` 的做法：`LayoutBuilder` 判 `constraints.maxWidth.isFinite` —— 有限则撑满（保持原有观感），无限则退化为内容宽度布局（不用 Spacer、不强制撑满）。

46. **widget 测试的两条硬约定** — ① 文本由 **`RichText`** 承载（不是 `Text` widget），`find.textContaining` / `find.text` 必须带 `findRichText: true`，否则静默返回 0 个匹配，会被误判成"渲染丢了内容"；② 帖子图片占位是 `CircularProgressIndicator`（无限动画），测试环境无法真正下载图片，`pumpAndSettle` **永不收敛**（表现为 `pumpAndSettle timed out`），必须改用固定帧 `pump()` + `pump(Duration)`。这两点在迁移中一次性误报了 9 个用例。

47. **测试报错要看「第一个」异常，不要被后续连锁异常带偏** — 表格 + 自定义组件崩溃时，日志尾部显示的是 `SelectionArea` 的 `_compareScreenOrder → RenderBox was not laid out`，看起来像选区/选择器问题；实际**第一个**异常才是根因：`BoxConstraints forces an infinite width`（发生在 `_TableRenderLayouter` 测量阶段，见 #45）。定位手段：把测试输出取 head 看第一条异常，或二分移除可疑组件（先去掉 `SelectionArea`，再逐个替换自定义组件）。

48. **转换层给渲染器写 HTML 时，不要依赖 `display:flex` 的收缩能力** — 旧渲染器根本不执行 `display:flex`，所以附件卡片里 `display:flex;gap:8px` + 文件名 `white-space:nowrap;text-overflow:ellipsis` + `flex:1;min-width:0` 一直"侥幸"不溢出；换成会执行 flex 的渲染器后，`flex:1` / `min-width:0` 不被支持（flex 子项拿到的仍是无限宽），长文件名（不可断行串）直接撑破容器 → `RenderHtmlFlex overflowed by N pixels`，并在帖子里画出黄黑警告条。修复：附件卡片改成**纯块级布局**（图标+文件名一行、大小/下载次数+下载链接一行），外观交给渲染层 `.bbcode-attach` 样式按主题提供。**通用规则：注入给渲染器的 HTML 里，任何"可能超长的内容"都不要放进横向 Row/flex；要么放进块级流（可换行），要么给它明确的有限宽度。**

49. **列表不用 `<ul>/<ol>/<li>`，在转换层展开为「带前缀的普通段落」** — 渲染器的列表标记是**悬挂在文字左侧**的（`html_list_item.dart` 把 marker 画在 `-盒宽 - 5` 处），因此每层嵌套都要额外预留一段 gutter；嵌套几层后正文被挤到没有宽度。而且标记盒宽是按固定文本 `'1.'` 量的（`html_list_marker.dart`），而 disc 圆点半径只有 `0.2em`，盒子比圆点宽约 5 倍，缩进怎么调都不对。**根治**：`BBCode2Html._convertLists` 直接输出 `<div>前缀 + 内容</div>`（有序拼 `1.`/`a.`/`A.`；无序默认不加前缀，改 `_kUnorderedMarkers` 可恢复 `•/◦/▪`）。嵌套多少层都不占额外宽度，左侧零留白。实现要点：① 用栈式配对切最外层 `[list...]` 块（**不能用 `outerBlocks()`**，它只认裸标签、匹配不到 `[list=1]`）；② 按最深层 `[*]` 切项，跳过嵌套列表内部的 `[*]`，并把 `[/*]`（部分编辑器的项结束标记）当分隔符；③ 切块时用 `block.length - '[/list]'.length` 而不是手写数字（曾写成 `- 9`，多切 2 个字符导致每块最后一项静默丢失）。
50. **widget 测试的默认字体每个字符都是 1em 宽，量出来的文本宽度不可直接当真实值** — 诊断列表标记时测到 `'1.'` = 32.5px @ fontSize 16（≈2em），据此差点把 `<ul>` 的内边距改大；真实字体下 `'1.'` ≈ 0.84em（≈13px）。**凡是要写死尺寸/内边距的地方，都用 em 或字号倍数表达，不要用测试里量出的 px 值反推**；若必须量化，先确认该宽度是否依赖字体（`TextPainter` + 默认字体 = 不可信）。

## 表情渲染管线

37. **表情是两段式管线，渲染层统一、问题常在 parse 层** — `HTML(<img smilieid>) → Html2BBCode（smilieid→[呵呵]）→ BBCode2Html（insertText→<img data-type="emoji">）`。渲染层只认 `[呵呵]` 文本：只要 bbcode 里没有，任何页面都渲染不出（"渲染层无米下锅"）。"最近回复预览没表情"的根因在 parse 层——`Html2BBCode` 按 `smilieIdMap` 匹配 `<img smilieid>`，匹配不到返回 `''` 静默丢弃。
38. **表情数据按站点隔离、解析层自取，不层层传递** — `EmojiService` 按站点 host 隔离维护 map/smilieIdMap/groups。`Html2BBCode._effectiveMap` 默认直接读 `EmojiService().smilieIdMap`，**为空则静默跳过**（"为空则什么也不做"，不报错）；`smilieIdMap` 构造参数仅保留给测试注入。不要在 API parse/export 层透传该参数（造成参数噪音，且 EmojiService 依赖 ApiService 有循环风险）。全局静态 `SmilieMap` 因此失去读取方成为孤儿，已删除（含 emoji_loader 内 3 处 update + core_app barrel export）。
39. **调用方在抓取前 `await EmojiService().load()` 保证数据就绪** — 否则与表情加载存在竞态丢表情；且预览缓存（SQLite，FIFO 100 条）会把坏 bbcode **固化**，表现为"历史问题"一直存在。修复后已固化的旧坏缓存不会自动修复，需清一次缓存或等自然淘汰。帖子详情（初始/翻页/预加载/刷新）、预览、引用帖、我的回复四处调用方均需在请求前 await load()。

84. **表情还原不能只认 `smilieid`：私信页的 `<img>` 没有该属性，必须用「smilieid 优先 + 图片路径保底」两段匹配** — 症状：帖子页表情正常，**私信会话里表情全按普通图片渲染**（`[img]https://…/static/image/smiley/qq/qq057.gif[/img]`，尺寸巨大、不再内联）。**根因**：`Html2BBCode` 原来只按 `smilieid` 属性匹配（`_effectiveMap`），而私信正文由 UCenter 渲染，表情 `<img>` **不带 `smilieid`** → 落入普通图片分支。判定依据（可复现）：`message.pm.view` 探针实测某条私信 bbcode 为 `…[img]https://bbs.binmt.cc/static/image/smiley/qq/qq057.gif[/img]…`——能产出 `[img]` 就说明 `smilieid` 为空（若属性存在但 map 未命中，代码会返回 `''` 丢弃，而不是 `[img]`）。**修法**：`EmojiService` 新增 `urlPathMap`（`insertTextMap` 反转成 **图片路径 → insertText**，懒构建、`map` 被替换时靠 `identical` 失效）；`Html2BBCode` 的 `<img>` 分支在 `smilieid` 之后补一层按 **`uri.path`** 反查（`_effectiveUrlMap`，可注入 `smileyUrlMap` 参数便于测试）。**为什么用 path 而不是完整 URL**：表情地址随「原站 / CDN」域名变化（`bbs.binmt.cc` vs `cdn.binmt.cc`），二者共用同一套 `/static/image/smiley/…` 路径，只比对 path 才不受域名影响。**配套**：私信页三处请求（首屏/翻页/轮询）前补 `await EmojiService().load()`，否则反查表为空仍退化为 `[img]`（同 #39）。验证：`test/emoji_diag_test.dart` 新增 5 例（smilieid 优先、路径反查、CDN/原站域名不同仍匹配、非表情图不误伤、表为空退化）。

## 测试驱动的渲染诊断

> 本节是渲染类 bug 的通用排查方法，与用哪个渲染器无关。#15 的示例代码
> 已按当前渲染器（flutter_widget_from_html）更新。

15. **先写测试看输出，再分析，不要上来就猜测** — 遇到 BBCode 渲染类 bug（空白、错位、布局异常），按三层链路逐层 dump 输出，用证据定位：
    - **AST 层**：`BBCodeParser().parse(bbcode)`，用 `JsonEncoder.withIndent('  ')` 打印 `toJson()`，确认解析器对结构的理解
    - **HTML 层**：`BBCode2Html().convert(bbcode)` 直接打印，检查标签结构（如 `<br>` 是否紧贴 `</ul>`）
    - **渲染树层**：widget test 里 `tester.pumpWidget(MaterialApp(home: Scaffold(body: HtmlWidget(html, ...))))`，然后遍历 `find.byType(RichText)` 打印**尺寸 + span 类型 + toPlainText**，看到每个段落的真实排版：
      ```dart
      for (final e in tester.elementList(find.byType(RichText))) {
        final rich = e.widget as RichText;
        final ro = e.renderObject as RenderParagraph?;
        print('${ro?.size}  "${jsonEncode(rich.text.toPlainText())}"');
      }
      ```
      `toPlainText()` 里 `￼`（OBJECT REPLACEMENT CHARACTER）代表 WidgetSpan（图片/内联块），`\n` 代表 `<br>`。**段落末尾的 `\n` 就是空行**。
17. **`\n → <br>` 与块级边界的通用规则** — `\n → <br>` 是无条件全局替换，BBCode 里换行常出现在块级标签（`[list]`/`[*]`/`[quote]`/`[align]`/`[td]`…）前后，这些 `<br>` 紧贴块级边界会被渲染成空行（如列表末尾图片下方的空白）。**不要逐个补特例正则**（永远有下一个嵌套组合），用一条通用规则替代：*移除与块级标签紧邻（中间仅空白）的 `<br>`，四个方向——开标签前 / 闭标签后 / 闭标签前 / 开标签后*。块级标签集合 `div|blockquote|ul|ol|li|table|tr|td|pre|hr`，未来新增块级标签只需加入集合。注意两点：① [code] 块在清理前已用占位符保护，其内部 `<li><br></li>`（保留行尾换行）不受影响；② **占位符盲区**——占位符还原后是块级标签（`[code]` → `<pre>`），但清理时看到的只是 `\x00CODE\d+\x00`，必须把 code 占位符也加入边界标签组，否则 `<br>` 会残留在图片与 code 块之间。
    **已知偏差（2026-09 实测）**：四个正则里 `_brAfterOpen` 的标签组漏了 `hr`（与本节声明的集合不一致），于是每个 `[hr]` 之后残留一个 `<br>`——整篇渲染比逐锚点渲染的预览多 16px/个 `[hr]`（见 #69）。修它会同时改变帖子详情页的 `[hr]` 呈现，故暂留未改。
18. **回归测试固定在渲染树层** — 只断言 HTML 字符串不够：转换层输出正确不代表渲染出来对（渲染器如何解释 HTML 是黑盒）。用 `testWidgets` 渲染后断言"含图片的段落以图片结尾、无末尾 `\n`"，才能直接锁住视觉 bug。同时用参数化用例覆盖多个嵌套组合，防止通用规则回归。
19. **Dart `replaceAll` 不展开 `$1`（JS 陷阱）** — `String.replaceAll(RegExp, '...$1...')` 会把 `$1` 当作**字面量**插入（JavaScript 才会展开）。需要取组时必须用 `String.replaceAllMapped(pattern, (m) => m[1]!)`。排查方法：写个 3 行探针测试确认行为，不要凭记忆写替换串。正则重构时若把 lookbehind + 空串替换改成捕获组，最容易踩此坑（`_brAfterClose`/`_brAfterOpen` 曾因此把字面 `$1` 插进 quote 引文）。
30. **Discuz 的 4 位短 hex 必须按 HTML legacy 语义归一化，否则颜色会丢** — 帖子里常见 `<font color="#ff00">`，Chrome 按 HTML color 属性的 legacy 语义把它渲染成红色 `rgb(255,0,0)`（4 位 = `#RRGG`，不是带 alpha 的 `#RGBA`）。若原样交给 `style="color:#ff00"`，渲染器按 CSS 解析会得到 alpha=0 的透明色——暗色主题下文字"发白/消失"，既不是黑也不是红。**修复**：`BBCode2Html._normalizeColor` 输出前归一化——4 位 `#RRGG` → `#RRGG00`（`#ff00` → `#ff0000`），3 位 `#RGB` → `#RRGGBB`；6/8 位、`rgb()`、命名色原样返回。接入 `color`/`backcolor`/`background` 三处。**验证**：`test/color_hex_diag_test.dart` 三层 dump（AST 值正确 → HTML 已归一化 → 渲染树 span 颜色为不透明红）。注意：编辑器预览（`lib/widgets/editor/editor_preview.dart` 的 `PostHtmlWidget`）与帖子渲染同走 `BBCode2Html._normalizeColor`（渲染在 `lib/widgets/bbcode/post_html_widget.dart`），颜色处理一致。

40. **widget 测试必须 `setUp` 里调用 `SiteStore.instance.init()`** — 否则 `SiteStore.current`（`_sites[0]`）越界抛 `RangeError`。测试环境无 Provider 时需 `ChangeNotifierProvider.value(value: SettingsProvider(), child: …)` 包裹渲染组件。
41. **`package:html` 会把 div 内裸 `td` foster-parent 移出父级** — 构造帖子测试 DOM 时，`<div><td class="t_f">` 中 td 会被 html 解析器提升到 table 层级，导致 `plc.querySelector('td.t_f')` 返回 null、bbcode 为空。必须按真实 Discuz 结构构造：`td.t_f` 位于 `div.t_fsz` 下的**嵌套 table** 内。排查方法：临时测试 `print(doc.body)` 看解析后 DOM。

78. **UI 布局/缩进"看着不对"别靠猜：widget 测试**量坐标** + **导出 PNG 复核** — 症状：MCP 能力开关展开内容的缩进连改三版（56 / 72 / 16）都不对，因为全靠肉眼看截图估像素。**根因**：Flutter 的真实偏移与直觉不符（如 `ListTile` 标题实测在 `16+24+16=56`，而非按 `minLeadingWidth(40)` 推出来的 72），且不同 DPR/字重下观感不同，截图估算不可靠。**修法（两条互补）**：① **量坐标** —— widget test 里 `tester.getTopLeft(find.text('...')).dx` 直接取真实 x，先 `print` 再 `expect` 锁死（当回归测试）；② **导 PNG 人眼复核** —— 被测页包一层 `RepaintBoundary(key: k)`，在 `tester.runAsync` 里 `(k.currentContext!.findRenderObject() as RenderRepaintBoundary).toImage(pixelRatio: 1)` → `toByteData(format: ui.ImageByteFormat.png)` → 写 `build/xxx.png`。**注意**：导出型探针放 `tool/`（不在 `flutter test` 默认范围内，不污染测试）；测试环境**无中文字体**（文字渲染成方块），PNG 只能看层级/缩进/块形状，坐标仍以 `getTopLeft` 为准。**教训**：凡"感觉不对但说不清哪里不对"的布局问题，先把真实坐标量出来、把图导出来再动手改——连续三版瞎改就是没这么做的代价。范例：`test/mcp_settings_layout_test.dart`（几何断言）、`tool/mcp_layout_snapshot_test.dart`（导出预览图）。
