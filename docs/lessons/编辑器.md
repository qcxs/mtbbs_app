## 编辑器

8. **撤销不自己实现** — Flutter UndoHistory（3.16+）代码量为 0，Bug 风险低。所有 BBCode 操作通过 `controller.value = newValue` 修改即可自动入栈。
9. **工具栏单一数据源** — `toolbar_config.dart` 控制所有项的枚举、默认顺序、快捷键、显隐。`BBCodeToolbar`、`EditorPage`、设置页都从此派生。
10. **工具栏切换为"只包裹+清除样式"** — 不再做"选中后切换"（如已有 `[b]` 时取消加粗），用户感受类似 Word 的 toggle。取消加粗只能通过 Undo 或 ClearStyles。
11. **编辑器不拦截 `Ctrl+Z`** — 让 `EditableText` 的 UndoHistory 自然处理。

69. **跨区定位只能靠"结构身份"，禁止"算偏移 / 文字匹配"** — 编辑器要让编辑区与预览区互相定位（点标记跳到另一侧；光标处只把标记换成箭头）。**走过的弯路**：按可见文字在渲染树里顺序匹配、`nearestY` 往上找最近行、把测量结果缓存起来事后纠偏、给各测量点加"过期标记"……越修越偏，**帖子越长偏得越多**。根因是两边本来就是两套渲染逻辑，任何"算出来的对应"都只是补丁，且必然被行内标签（`[b]`/`[color]`/表情）、异步撑开（图片加载完把整篇往下推）、改窗口宽度逐一破坏——测试再充分也覆盖不住真实帖子。**现方案**（三个模块，缺一不可）：`core/parser/bbcode_anchors.dart` 把源码切成**锚点**（顶层块 ∪ 文本块内每一行；跨行标签内部的行首不切，否则两块各带半个标签；锚点是**原文切片**，行内标签在切片内部，动不了锚点边界）；`widgets/editor/editor_preview.dart` 把预览改成**逐锚点渲染**（每个锚点一个 `PostHtmlWidget` + `GlobalKey`）；`pages/editor/editor_page_locator.dart` 负责"两边同源 + 点标记跳转"（光标移动只刷新箭头，**不自动滚动**；只在锚点变化时才 `setState`）。**两边共用同一份锚点表，下标就是对应关系**；位置在要用的时候 `findRenderObject()` → `localToGlobal` **现场读**，不缓存、不估算，所以没有"过期快照"这回事。硬不变量：`anchors.map((a) => a.raw).join() == 原文`（切分只切分、不改写）。**配套代价**（实测，可接受）：纯段落 / 连续行 / 图片交替总高逐像素一致；块级边界（列表 / 表格 / 代码、隐藏 / 免费 / 对齐）有 ±8~32px 的空白差异，不累及段落内部 —— 探针 `tool/anchor_fidelity_probe_test.dart` 随时复跑。**下次想"再加个测量补丁"时，先回答一句：这个锚点的结构身份是什么？**

70. **Windows 上 "Failed to update ui::AXTree" 刷屏只能在 Dart 侧"让它没内容"，关不掉** — 现象：打字时控制台被 `[ERROR:flutter/shell/platform/common/accessibility_bridge.cc(114)] Failed to update ui::AXTree, error: NNN … will not be in the tree and is not the new root` 刷屏（错误码会变，910 / 14 都见过）。**根因在引擎**：只要系统侧有 UIA 客户端在观察窗口（读屏、自动化工具、部分输入法），Windows embedder 就会启用 `accessibility_bridge`；此后每次重建都可能走进 `AccessibilityBridge::CommitUpdates()` 的失败分支——框架送来的节点 id 与 AX 树对不上，`tree_->error()` 非空就直接打 ERROR 并 `return`。**先试过但不够**（只减少抖动，日志照旧）：预览整体 `ExcludeSemantics`；标记槽 `ExcludeSemantics` + `Tooltip(excludeFromSemantics: true)`；光标同锚点内不重建。**最终做法**：`MaterialApp.router` 的 `builder` 里把整棵树包进 `ExcludeSemantics`（`lib/main.dart`）——本 App 不为无障碍设计，语义树恒为空 → 没有节点更新 → 刷屏消失。**三点注意**：① 这是"整个 App 关闭无障碍"，读屏软件读不到任何内容，要恢复只需删掉那一层；② 若某输入法/工具依赖 UIA 取光标位置，需实测（Flutter 的 IME 走 TSF，通常不受影响）；③ 该日志只在开发时有控制台可见，release 不刺眼——**别为它去做架构妥协**。
