>
> 条目编号沿用历史序号（`docs/` 其他篇与测试注释都在按编号引用，见 #30、#37-39 等），
> 因此章节内的编号不连续。**检索请认编号，不要认位置。**

## 解析相关

1. **Discuz inajax 的 content-type** — 只有少量页面返回 XML，多数返回 HTML（"discuz_uid" 标记），还有 JSON 或纯文本。**不要假设 content-type**，以响应内容为准。
2. **优先 DOM 解析**（`xml_helper.dart`）—— 即使 HTML 不规范也优先 DOM，正则只用于 DOM 无法处理的场景（如行内表情、签名混合内容）。
3. **`parseSubmitResponse` 统一入口** — 所有表单提交的响应解析走此函数，它处理 `succeed`、`alert`、`location` 等 Discuz 通用返回格式。

## 状态与导航

4. **`Navigator.maybePop` vs `canPop + pop`** — `canPop` 检查 `Navigator`，非 GoRouter。在 GoRouter shell 环境下，`Navigator.canPop` 可能返回 false 但 `GoRouter.canPop()` true。
5. **`showModalBottomSheet` 数据同步** — 面板关闭重开会重建 State，内部 State 会丢。数据源用 Provider（面板内 `context.watch` 实时读）或 `ValueNotifier` / 回调，不要在面板里自持一份副本。
6. **双击退出** — 只在 Android 返回键触发，Esc 不做。
7. **站点切换顺序** — `saveCurrentSiteState()` → `SiteConfig.switchTo()` → Provider reload，不可颠倒。

## 编辑器

8. **撤销不自己实现** — Flutter UndoHistory（3.16+）代码量为 0，Bug 风险低。所有 BBCode 操作通过 `controller.value = newValue` 修改即可自动入栈。
9. **工具栏单一数据源** — `toolbar_config.dart` 控制所有项的枚举、默认顺序、快捷键、显隐。`BBCodeToolbar`、`EditorPage`、设置页都从此派生。
10. **工具栏切换为"只包裹+清除样式"** — 不再做"选中后切换"（如已有 `[b]` 时取消加粗），用户感受类似 Word 的 toggle。取消加粗只能通过 Undo 或 ClearStyles。
11. **编辑器不拦截 `Ctrl+Z`** — 让 `EditableText` 的 UndoHistory 自然处理。

## 图片

12. **图片查看器用 `photo_view`，不要自己实现** — 手势冲突和缩放动画自己写很难做对，前两版自研实现均已废弃。
13. **图片上传/下载不要用论坛的 `ApiService().dio`** — 图床等第三方域不兼容论坛 Dio 的请求头，上传走独立 Dio；图片下载走 `IgnoreCacheFileService`，过期天数由 `cacheExpire` 配置（`assets/config/defaults.json`，见 docs/01「图片缓存规范」）。
14. **`file_picker` 默认压缩图片（GIF→JPG 陷阱）** — `FilePicker.platform.pickFiles(type: FileType.image)` 在 Android 端默认 `allowCompression: true`，Java 端 `FileUtils.compressImage()` 会把图片解码为 Bitmap 后重新压缩为 **JPEG**（硬编码 `Bitmap.CompressFormat.JPEG`），导致：
    - GIF 丢失动画、变为静态 JPG
    - PNG 等格式被强制转为 JPG
    - 分辨率被压缩（默认 `compressionQuality: 30`）
    
    **修复**：所有 `FilePicker` 调用加 `allowCompression: false`。
    
    这是插件自身行为（AOSP 原生相册即可复现），不要误判成系统相册转格式。验证方法：抓 `FilePickerUtils` 日志，出现 `JPEG_时间戳_.jpg` 即命中。

## BBCode 渲染架构（占位元素 + 自定义组件注入）

> 渲染器已在 2026-09 从 flutter_html 换成 flutter_widget_from_html（见下方
> #43-50）。本节只保留跨渲染器仍然成立的规则：占位元素机制现在只服务
> `[code]`；`[table]` 由转换层直接输出 `<table>`，交给渲染器原生渲染。

31. **一次转换 + 占位元素，根治"分段拆散容器"类 bug** — `[hide]内容[code]…[/code]内容[/hide]` 里 hide 失效、原样显示文本的根因：按 code/table 切段后各段独立渲染，hide/quote/free 等容器的开闭标签被拆到不同片段 → 配对失败 → 原样输出。**根治**：不再分段，`BBCode2Html` 一次转换，`[code]` 还原为占位元素 `<div data-code-index="N">`，渲染器的 `customWidgetBuilder` 原地替换为 `BbcodeCodeBlock`（`post_html_widget.dart`）。容器结构在单次转换中天然完整，任意嵌套安全。代码原文存 converter 公开字段 `codeBlocks`（索引即占位符编号），越界时返回空组件、不崩溃。
33. **非法 hex 颜色必须在转换层丢弃，不能让渲染器去兜底** — `[color=#FFYYTT]` 会原样进入 `<span style="color:#FFYYTT">`，渲染器拿到非法值可能直接抛异常，连累整段甚至整篇渲染失败。**规则**：`BBCode2Html._normalizeColor` 只放行 `#` 后 3/4/6/8 位 hex，非法返回空串、调用点省略 style。与 #30 是两件事：一个"值非法要丢"，一个"值合法但语义要纠正"。
34. **嵌套 BBCode 用栈式配对，不用非贪婪正则** — 非贪婪 `[\s\S]*?` 会被内层 `[/table]`/`[/td]`/`[/tr]` 截断，导致 table 套 table、tr 内嵌 table 解析错位。用 `outerBlocks(input, tag)`（计数配对最外层）：`RegExp('\\[/?$tag\\]', caseSensitive: false)` 遍历，开标签 depth++、闭标签 depth--，depth 归零时产出 `(start, end)`。**Dart 陷阱**：必须用非原始字符串 `'\\[/?$tag\\]'`——`r'\[/?$tag\]'` 会把 `$tag` 当字面量（不插值）；另 `RegExp.firstMatch` 无 start 参数，需要偏移量时用 `substring(match.end)` 切片。
42. **编辑器附件链路：attachimg/attach 在编辑器侧转成 appdata，渲染层不可知** — 编辑器插入的是 Discuz 原生标签 `[attachimg]aid[/attachimg]` / `[attach]aid[/attach]`（正文按原样 POST，交给 Discuz 服务器渲染；同时提取 aid 绑定表单 `attachnew`）。**预览前**由 `_preparePreviewBbcode`（`editor_page.dart`）把二者替换为 `[appdata]{"type":"image_attach"|"attach", …}[/appdata]`，数据来自 `_aidToSrc` / `_aidToAttachment`（在页面抓取、快照恢复、上传成功时填充）；渲染层 `BBCode2Html` 只认 `[appdata]`，对 attachimg/attach 没有规则。**数据缺失时保留原标签是有意设计**：用户看到 `[attachimg]123[/attachimg]` 原文即知 aid 插错了，不要改成占位 appdata（那会掩盖错误 id）。

## 渲染引擎迁移：flutter_html → flutter_widget_from_html（2026-09）

43. **块级 / 内联由 `customWidgetBuilder` 的返回值决定，这是"表情内联 + 图片块级"共存的正解** — 返回 `InlineCustomWidget` → 占位符进入文字行内（`toPlainText()` 里表现为 `￼`）；返回普通 Widget → 独占一行的块级元素。同一份 `<img>` 用 `data-type="emoji"` 区分即可走两条路径，不再需要靠类型白名单和"有没有显式尺寸"去猜。判定实现在 `core_build_tree.dart`（`customWidget is InlineCustomWidget` 分支）。

44. **链接内图片的点击可以冒泡，因此图片组件绝不能挂 `onTap`** — 渲染器对 inline A 标签会把它内部的**块级**子元素逐个 `wrapWith(buildGestureDetector)`（`internal/ops/tag_a.dart`），把链接手势下沉到图片上。所以帖子图片只挂 `onLongPress`（长按菜单），点击就会自然冒泡到外层 `[url]`。挂了 `onTap` 反而会抢走点击，"点击图片跳链接"和"点击图片看大图"不能同时要。

45. **注入到表格单元格的块级组件必须容忍无限宽约束** — 表格列总宽超过可用宽时，渲染器会套一层横向滚动，测量单元格时下发 `w=Infinity`。此时 `Container(width: double.infinity)`、`Spacer`、`MainAxisSize.max` 都会抛 `BoxConstraints forces an infinite width`，**并中断整张表甚至整篇帖子的渲染**。`BbcodeCodeBlock` 的做法：`LayoutBuilder` 判 `constraints.maxWidth.isFinite` —— 有限则撑满（保持原有观感），无限则退化为内容宽度布局（不用 Spacer、不强制撑满）。

46. **widget 测试的两条硬约定** — ① 文本由 **`RichText`** 承载（不是 `Text` widget），`find.textContaining` / `find.text` 必须带 `findRichText: true`，否则静默返回 0 个匹配，会被误判成"渲染丢了内容"；② 帖子图片占位是 `CircularProgressIndicator`（无限动画），测试环境无法真正下载图片，`pumpAndSettle` **永不收敛**（表现为 `pumpAndSettle timed out`），必须改用固定帧 `pump()` + `pump(Duration)`。这两点在迁移中一次性误报了 9 个用例。

47. **测试报错要看「第一个」异常，不要被后续连锁异常带偏** — 表格 + 自定义组件崩溃时，日志尾部显示的是 `SelectionArea` 的 `_compareScreenOrder → RenderBox was not laid out`，看起来像选区/选择器问题；实际**第一个**异常才是根因：`BoxConstraints forces an infinite width`（发生在 `_TableRenderLayouter` 测量阶段，见 #45）。定位手段：把测试输出取 head 看第一条异常，或二分移除可疑组件（先去掉 `SelectionArea`，再逐个替换自定义组件）。

48. **转换层给渲染器写 HTML 时，不要依赖 `display:flex` 的收缩能力** — 旧渲染器根本不执行 `display:flex`，所以附件卡片里 `display:flex;gap:8px` + 文件名 `white-space:nowrap;text-overflow:ellipsis` + `flex:1;min-width:0` 一直"侥幸"不溢出；换成会执行 flex 的渲染器后，`flex:1` / `min-width:0` 不被支持（flex 子项拿到的仍是无限宽），长文件名（不可断行串）直接撑破容器 → `RenderHtmlFlex overflowed by N pixels`，并在帖子里画出黄黑警告条。修复：附件卡片改成**纯块级布局**（图标+文件名一行、大小/下载次数+下载链接一行），外观交给渲染层 `.bbcode-attach` 样式按主题提供。**通用规则：注入给渲染器的 HTML 里，任何"可能超长的内容"都不要放进横向 Row/flex；要么放进块级流（可换行），要么给它明确的有限宽度。**

49. **列表不用 `<ul>/<ol>/<li>`，在转换层展开为「带前缀的普通段落」** — 渲染器的列表标记是**悬挂在文字左侧**的（`html_list_item.dart` 把 marker 画在 `-盒宽 - 5` 处），因此每层嵌套都要额外预留一段 gutter；嵌套几层后正文被挤到没有宽度。而且标记盒宽是按固定文本 `'1.'` 量的（`html_list_marker.dart`），而 disc 圆点半径只有 `0.2em`，盒子比圆点宽约 5 倍，缩进怎么调都不对。**根治**：`BBCode2Html._convertLists` 直接输出 `<div>前缀 + 内容</div>`（有序拼 `1.`/`a.`/`A.`；无序默认不加前缀，改 `_kUnorderedMarkers` 可恢复 `•/◦/▪`）。嵌套多少层都不占额外宽度，左侧零留白。实现要点：① 用栈式配对切最外层 `[list...]` 块（**不能用 `outerBlocks()`**，它只认裸标签、匹配不到 `[list=1]`）；② 按最深层 `[*]` 切项，跳过嵌套列表内部的 `[*]`，并把 `[/*]`（部分编辑器的项结束标记）当分隔符；③ 切块时用 `block.length - '[/list]'.length` 而不是手写数字（曾写成 `- 9`，多切 2 个字符导致每块最后一项静默丢失）。
50. **widget 测试的默认字体每个字符都是 1em 宽，量出来的文本宽度不可直接当真实值** — 诊断列表标记时测到 `'1.'` = 32.5px @ fontSize 16（≈2em），据此差点把 `<ul>` 的内边距改大；真实字体下 `'1.'` ≈ 0.84em（≈13px）。**凡是要写死尺寸/内边距的地方，都用 em 或字号倍数表达，不要用测试里量出的 px 值反推**；若必须量化，先确认该宽度是否依赖字体（`TextPainter` + 默认字体 = 不可信）。

## 设置页信息架构

51. **设置项「存在」不等于「找得到」：同一个能力的入口分散 = 用户眼里的两套设置** — 重构前的实际状态：`themeMode`（浅色/深色/跟随系统）只在「我的」页顶部的按钮里，设置页「界面」组只有主题色和纯黑主题；`docs/08` 当时写着"设置 → 夜间模式"，用户按文档进设置页找不到；设置搜索也搜不到（搜索只索引设置页自己的分组模型）。**规则**：凡是"设置项"，就必须能用一句话从设置页走到；页内快捷入口（如「我的」页的模式按钮）只能**调用同一个弹窗函数**（`showThemeModeDialog`），不能另写一份 `AlertDialog`。
52. **分组按"用户关心什么"划分，不按"代码归属"划分** — 「通用错峰间隔」原本放在「关于」组（因为它在 `stagger_queue.dart` 里），对用户毫无线索；「插入格式」是编辑器引用格式却放在「内容渲染」。现行为 5 组：站点与网络 / 外观 / 阅读与渲染 / 编辑与快捷键 / 存储与工具，「关于」降为列表底部单独一行、不占分组位。
53. **"只有查看 + 一个操作"的页面应该降级为底部面板** — 表情管理（唯一动作"重新获取"）、MT 图床管理（只有隐藏/删除）原先各占一个路由和 Scaffold，属于"点进去再点进去"。降级方式：把页面拆成 `showXxxSheet(context)` + 无 Scaffold 的内容 widget，路由删除，`showModalBottomSheet(isScrollControlled: true, constraints: BoxConstraints(maxWidth: 560, maxHeight: 600))`。内容 widget 用 `Column(children: [拖拽手柄, 标题行, Divider, Expanded(列表)])` —— **`Expanded` 依赖 `constraints` 给的上界，所以 `constraints` 必须给 `maxHeight`，否则 unbounded 直接崩**。反之，表单重、需要实时预览的页（缓存管理、编辑器设置、插入格式）保持独立页。
54. **同一个功能有两份渲染实现时，删掉的是"实现"而不是"入口"** — `shortcut_settings_page.dart`（170 行）与 `models/shortcut_settings.dart`（98 行的声明式模型）渲染同一份数据，改一处漏一处。现在只保留模型 + 一个 `showShortcutSheet()`，设置页和编辑器设置页都调它（两个入口、一份实现）。

## 首页信息架构

55. **折叠状态不能用显示标题当 key** — 原实现 `_expandedSections = {'排行', 'RSS'}` 拿中文标题做标识：改文案即静默失效、重启 App 全部复位、用户也无法配置。现改为稳定 id（`shortcuts` / `forums` / `rank` / `rss`），持久化为 `ManagedItem` 列表、展开状态放 `data['expanded']`。首页里当场折叠与设置面板里改默认值走**同一个** `setHomeSectionExpanded()` —— 所以"记住我的操作"和"可改默认"原本是同一条状态，不需要两套。
56. **`AnimatedCrossFade` 的折叠是假的：两个 child 都常驻 widget tree** — 折叠状态下 `RanklistSection.initState` 照跑 `_fetch()`，`RssSection` 同理："折叠"只省了屏幕空间，网络请求和内存一份没省，用户折叠掉不看的区块，每次进首页照样请求。要真正做到"折叠就不请求"，必须让子树**有条件地不构建**：`AnimatedSize(child: expanded ? 内容 : SizedBox(width: double.infinity))` —— 高度过渡保留，折叠时子树直接消失。
57. **区块标题只渲染一层** — `_CollapsibleSection(title: 'RSS 订阅')` 外层已有标题，`RssSection` 内部又画了一个同名标题栏，展开后页面上同时出现两个"RSS 订阅"。**规则**：内容组件不自带标题，标题一律由容器提供；否则换容器（卡片 / 弹窗 / 独立页）时必然重复。
58. **首页区块的顺序 + 显隐 + 默认展开共用一个 `ManagedItem` 列表** — `data` 是业务自定义字段的收纳位（这里放 `expanded`），顺序即列表顺序，持久化一个 key（`homeSections`）。设置面板用 `ReorderableListView` + 拖拽手柄 / 默认展开 Switch / 可见性按钮三个控件复用同一份数据。新增区块只需往 `_homeSectionDefaults` 加一行，加载时按 id 白名单过滤损坏数据。
59. **区块列表不要按"列"分，宽度交给区块内部消化** — 首页曾在宽屏下把区块交替分到左右两列，结果左右高度必然不等（快捷链接 2 行、排行 10 条，差得远），比单列更乱。根因是**区块高度由内容决定，布局阶段无法拉平**；瀑布流能对齐列高但会打乱顺序。现在的做法：单列纵向 + 区块内部自适应宽度（快捷链接按容器宽度加列，版块 `Wrap` 铺开，排行自己按 `maxWidth > 600` 双列）。宽屏只额外增加页面左右边距。
60. **网格的"列数"要由容器宽度反推，不能写死** — `crossAxisCount: 4` 写死时格子宽度 = 容器宽 / 4，于是宽屏下格子被撑到 100+ px 却"一行还是 4 个"，窄屏又显得挤。改成目标格子宽度驱动：`columns = max(3, ceil(containerWidth / (targetTileWidth + spacing)))`，超宽屏会一直加列而格子尺寸恒定（这里稳定在 53~56px）。首屏"两行"的数量也要跟着算：`initialCount = columns * 2`。

## 表情渲染管线

37. **表情是两段式管线，渲染层统一、问题常在 parse 层** — `HTML(<img smilieid>) → Html2BBCode（smilieid→[呵呵]）→ BBCode2Html（insertText→<img data-type="emoji">）`。渲染层只认 `[呵呵]` 文本：只要 bbcode 里没有，任何页面都渲染不出（"渲染层无米下锅"）。"最近回复预览没表情"的根因在 parse 层——`Html2BBCode` 按 `smilieIdMap` 匹配 `<img smilieid>`，匹配不到返回 `''` 静默丢弃。
38. **表情数据按站点隔离、解析层自取，不层层传递** — `EmojiService` 按站点 host 隔离维护 map/smilieIdMap/groups。`Html2BBCode._effectiveMap` 默认直接读 `EmojiService().smilieIdMap`，**为空则静默跳过**（"为空则什么也不做"，不报错）；`smilieIdMap` 构造参数仅保留给测试注入。不要在 API parse/export 层透传该参数（造成参数噪音，且 EmojiService 依赖 ApiService 有循环风险）。全局静态 `SmilieMap` 因此失去读取方成为孤儿，已删除（含 emoji_loader 内 3 处 update + core_app barrel export）。
39. **调用方在抓取前 `await EmojiService().load()` 保证数据就绪** — 否则与表情加载存在竞态丢表情；且预览缓存（SQLite，FIFO 100 条）会把坏 bbcode **固化**，表现为"历史问题"一直存在。修复后已固化的旧坏缓存不会自动修复，需清一次缓存或等自然淘汰。帖子详情（初始/翻页/预加载/刷新）、预览、引用帖、我的回复四处调用方均需在请求前 await load()。

## 测试驱动的渲染诊断

> 本节是渲染类 bug 的通用排查方法，与用哪个渲染器无关。#15 的示例代码
> 已按当前渲染器（flutter_widget_from_html）更新。

15. **先写测试看输出，再分析，不要上来就猜测** — 遇到 BBCode 渲染类 bug（空白、错位、布局异常），按三层链路逐层 dump 输出，用证据定位：
    - **AST 层**：`BBCodeParser().parse(bbcode)`，用 `JsonEncoder.withIndent('  ')` 打印 `toJson()`，确认解析器对结构的理解
    - **HTML 层**：`BBCode2Html().convert(bbcode)` 直接打印，检查标签结构（如 `<br>` 是否紧贴 `</ul>`）
    - **渲染树层**：widget test 里 `tester.pumpWidget(MaterialApp(home: Scaffold(body: HtmlWidget(html, ...))))`，然后遍历 `find.byType(RichText)` 打印**尺寸 + span 类型 + toPlainText**，看到每个段落的真实排版：
      ```dart
      for (final e in tester.elementList(find.byType(RichText))) {
        final rich = e.widget as RichText;
        final ro = e.renderObject as RenderParagraph?;
        print('${ro?.size}  "${jsonEncode(rich.text.toPlainText())}"');
      }
      ```
      `toPlainText()` 里 `￼`（OBJECT REPLACEMENT CHARACTER）代表 WidgetSpan（图片/内联块），`\n` 代表 `<br>`。**段落末尾的 `\n` 就是空行**。
17. **`\n → <br>` 与块级边界的通用规则** — `\n → <br>` 是无条件全局替换，BBCode 里换行常出现在块级标签（`[list]`/`[*]`/`[quote]`/`[align]`/`[td]`…）前后，这些 `<br>` 紧贴块级边界会被渲染成空行（如列表末尾图片下方的空白）。**不要逐个补特例正则**（永远有下一个嵌套组合），用一条通用规则替代：*移除与块级标签紧邻（中间仅空白）的 `<br>`，四个方向——开标签前 / 闭标签后 / 闭标签前 / 开标签后*。块级标签集合 `div|blockquote|ul|ol|li|table|tr|td|pre|hr`，未来新增块级标签只需加入集合。注意两点：① [code] 块在清理前已用占位符保护，其内部 `<li><br></li>`（保留行尾换行）不受影响；② **占位符盲区**——占位符还原后是块级标签（`[code]` → `<pre>`），但清理时看到的只是 `\x00CODE\d+\x00`，必须把 code 占位符也加入边界标签组，否则 `<br>` 会残留在图片与 code 块之间。
18. **回归测试固定在渲染树层** — 只断言 HTML 字符串不够：转换层输出正确不代表渲染出来对（渲染器如何解释 HTML 是黑盒）。用 `testWidgets` 渲染后断言"含图片的段落以图片结尾、无末尾 `\n`"，才能直接锁住视觉 bug。同时用参数化用例覆盖多个嵌套组合，防止通用规则回归。
19. **Dart `replaceAll` 不展开 `$1`（JS 陷阱）** — `String.replaceAll(RegExp, '...$1...')` 会把 `$1` 当作**字面量**插入（JavaScript 才会展开）。需要取组时必须用 `String.replaceAllMapped(pattern, (m) => m[1]!)`。排查方法：写个 3 行探针测试确认行为，不要凭记忆写替换串。正则重构时若把 lookbehind + 空串替换改成捕获组，最容易踩此坑（`_brAfterClose`/`_brAfterOpen` 曾因此把字面 `$1` 插进 quote 引文）。
30. **Discuz 的 4 位短 hex 必须按 HTML legacy 语义归一化，否则颜色会丢** — 帖子里常见 `<font color="#ff00">`，Chrome 按 HTML color 属性的 legacy 语义把它渲染成红色 `rgb(255,0,0)`（4 位 = `#RRGG`，不是带 alpha 的 `#RGBA`）。若原样交给 `style="color:#ff00"`，渲染器按 CSS 解析会得到 alpha=0 的透明色——暗色主题下文字"发白/消失"，既不是黑也不是红。**修复**：`BBCode2Html._normalizeColor` 输出前归一化——4 位 `#RRGG` → `#RRGG00`（`#ff00` → `#ff0000`），3 位 `#RGB` → `#RRGGBB`；6/8 位、`rgb()`、命名色原样返回。接入 `color`/`backcolor`/`background` 三处。**验证**：`test/color_hex_diag_test.dart` 三层 dump（AST 值正确 → HTML 已归一化 → 渲染树 span 颜色为不透明红）。注意：编辑器预览走 `PostAstWidget._parseColor`（仅命名色，hex 一律回退黑），是同一根因的另一表现。

40. **widget 测试必须 `setUp` 里调用 `SiteStore.instance.init()`** — 否则 `SiteStore.current`（`_sites[0]`）越界抛 `RangeError`。测试环境无 Provider 时需 `ChangeNotifierProvider.value(value: SettingsProvider(), child: …)` 包裹渲染组件。
41. **`package:html` 会把 div 内裸 `td` foster-parent 移出父级** — 构造帖子测试 DOM 时，`<div><td class="t_f">` 中 td 会被 html 解析器提升到 table 层级，导致 `plc.querySelector('td.t_f')` 返回 null、bbcode 为空。必须按真实 Discuz 结构构造：`td.t_f` 位于 `div.t_fsz` 下的**嵌套 table** 内。排查方法：临时测试 `print(doc.body)` 看解析后 DOM。

## 通用

20. **CSS 属性提取必须锚定声明起点** — 用正则提取内联样式时，`'color\\s*:\\s*([^;]+)'` 这类**未锚定**的写法会把 `background-color:green` 误判为 `color:green`（`color` 是 `background-color` 的后缀），导致 `<font style="background-color:green">` 被转成 `[background=green][color=green]...[/color][/background]` 多套一层。修复：`(?:^|;)\s*${属性名}\s*:\s*([^;]+)`，锚定到声明起点。

21. **MCP 工具优先** — 新增 API 时先用 Chrome MCP 确认请求/响应格式，再写 Dart 代码。
22. **日志强制 AppLogger** — 严禁 `print`/`debugPrint`。注：lint 未做强制阻断——`avoid_print` 在 `analysis_options.yaml` 被 ignore（放行 `tool/` 探针与测试文件的 print），生产代码靠约定执行。
23. **跨 Widget 状态传递用统一实例，不要层层回调** — 同组件树内用 Controller 实例（如 `BBCodeToolbarController`），全局配置用 Provider，都比多层回调易维护。
24. **编辑器页面必须用 PC UA** — 编辑器的 DOM 解析（`PageFetcher.parsePage`）依赖 Discuz PC 版的 HTML 结构（`textarea#e_textarea`、`input#subject`、`a[id^=imageattach]` 等）。用移动 UA 拿到的页面表单字段为空、图片/附件列表无法识别。现在 `ApiService` 默认就是 `Site.uaPc`，编辑器 `fetchPage` 再显式覆写一次——两处都不要改成移动 UA。
25. **UA 才是决定 Discuz 模板的开关，`mobile=2` 只是辅助** — Discuz 按 `User-Agent` 决定返回移动版还是 PC 版 HTML，`mobile=2` 只影响页面内少量呈现。不要靠 `mobile=2` 去"切版本"以适配解析（解析逻辑依赖的是 UA 对应的 HTML 结构）；只有登录页这类需要移动版表单的页面才保留该参数（见 `web_login_page.dart`）。
26. **Cookie 解析需要异常保护** — Discuz 的部分 Cookie 值包含逗号（如 `discuz_lastvisit=ts1,ts2,ts3`），Dart `dart:io` 的 `Cookie(name, value)` 构造函数严格遵循 RFC 6265，禁止 value 中出现逗号，抛出 `FormatException`。修复：`_parseCookieString` 中 `try/catch` 跳过非法 Cookie。
27. **一律用 `package:mtbbs/...` 绝对导入，不用 `../` 相对导入** — 移动文件时不需要改 import。目录重组（`widgets/`、`core/` 分子目录）时已统一转过一次；barrel 文件见 `config/`、`models/`、`widgets/`、`core/core_parsers.dart`。
28. **`file_picker` 选取文件时无条件复制缓存副本（Android/iOS）** — 插件 Java 端 `FileUtils.openFileStream()` 在**每次选取**时都把文件复制到 `{getCacheDir()}/file_picker/{时间戳}/{文件名}`，与 `withReadStream`/`withData`/`allowCompression` 都无关——`allowCompression: false` 只绕过了 JPEG 压缩（见 #14），不阻止落盘。该缓存**无自动清理**，插件要求 App 主动调 `FilePicker.platform.clearTemporaryFiles()`（Android 端即递归删 `file_picker/` 目录）；桌面端直接返回原路径不复制，故仅移动端有此问题（Windows 上缓存管理页该项恒为 0）。**修复**：缓存管理页新增「文件选择器缓存」项（复用 `getCacheInfo('file_picker')` / `clearCacheByKey('file_picker')`，即 `{tempDir}/file_picker`）；图片、附件、图床三处上传成功后调 `deleteFilePickerTempIfAny(path)` 自删（仅删 `{tempDir}/file_picker/` 下的副本，按路径前缀严格校验，绝不触碰用户原图；剪贴板图片走 `mtbbs_clip/` 不受影响）。

## 写操作 API

29. **Discuz 默认操作 API 直接拼接 URL，不要从 DOM 提取入口** — 点赞（`action=recommend`）、评分（`action=rate`）等 Discuz 自带操作，URL 是固定的通用格式：`forum.php?mod=misc&action=rate&tid={tid}&pid={pid}`（加 `&inajax=1` 取弹窗/响应），用页面已有的 tid/pid 直接拼即可。**不要**专门去帖子 DOM 里定位评分/点赞按钮再提取 onclick/href——按钮 DOM 位置随模板变化（标准 Discuz 在 `.po .pob.cl`，克米在第二个 `td.plc` 的 `#p_btn`）、onclick 里的路径可能带或不带前导斜杠，为每个模板适配提取逻辑纯属浪费时间，且"按钮取不到"会让整个功能不可用。**DOM 提取唯一必要场景是需要页面其他位置拿不到的参数（如收藏的 favid）；需要 formHash 时直接用页面全局 formhash**——一个页面所有表单共用一个，取任意 `<input name="formhash">` 即可，比定位特定功能的表单更通用。教训：评分功能曾大量时间耗在"评分按钮在第几个 td.plc、onclick 有没有前导 `/`"上，实际一行拼接 URL 就解决；入口对无权限/已评分的用户本就该由弹窗响应拦截（提示信息无 `<form>` → 抛 FormatException），不该靠"有没有按钮"来体现。
