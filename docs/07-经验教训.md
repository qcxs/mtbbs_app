# 经验教训

## 解析相关

1. **Discuz inajax 的 content-type** — 只有少量页面返回 XML，多数返回 HTML（"discuz_uid" 标记），还有 JSON 或纯文本。**不要假设 content-type**，以响应内容为准。
2. **优先 DOM 解析**（`xml_helper.dart`）—— 即使 HTML 不规范也优先 DOM，正则只用于 DOM 无法处理的场景（如行内表情、签名混合内容）。
3. **`parseSubmitResponse` 统一入口** — 所有表单提交的响应解析走此函数，它处理 `succeed`、`alert`、`location` 等 Discuz 通用返回格式。

## 状态与导航

4. **`Navigator.maybePop` vs `canPop + pop`** — `canPop` 检查 `Navigator`，非 GoRouter。在 GoRouter shell 环境下，`Navigator.canPop` 可能返回 false 但 `GoRouter.canPop()` true。
5. **`showModalBottomSheet` 数据同步** — 关闭重开会重建 State，用 `ValueNotifier` / 回调而非内部 State 保持数据同步。
6. **双击退出** — 只在 Android 返回键触发，Esc 不做。
7. **站点切换顺序** — `saveCurrentSiteState()` → `SiteConfig.switchTo()` → Provider reload，不可颠倒。

## 编辑器

8. **撤销不自己实现** — Flutter UndoHistory（3.16+）代码量为 0，Bug 风险低。所有 BBCode 操作通过 `controller.value = newValue` 修改即可自动入栈。
9. **工具栏单一数据源** — `toolbar_config.dart` 控制所有项的枚举、默认顺序、快捷键、显隐。`BBCodeToolbar`、`EditorPage`、设置页都从此派生。
10. **工具栏切换为"只包裹+清除样式"** — 不再做"选中后切换"（如已有 `[b]` 时取消加粗），用户感受类似 Word 的 toggle。取消加粗只能通过 Undo 或 ClearStyles。
11. **编辑器不拦截 `Ctrl+Z`** — 让 `EditableText` 的 UndoHistory 自然处理。

## 图片

12. **图片查看器 → photo_view** — v3 版改用 `photo_view` 包，解决手势冲突和缩放动画，之前的两版（自己实现）已废弃。
13. **图片上传用独立 Dio** — CDT（Content Delivery Network）不兼容论坛 Dio 的请求头，图片缓存走 `IgnoreCacheFileService`（自定义 30 天/7 天有效期），不用 `ApiService().dio` 下载。
14. **`file_picker` 默认压缩图片（GIF→JPG 陷阱）** — `FilePicker.platform.pickFiles(type: FileType.image)` 在 Android 端默认 `allowCompression: true`，Java 端 `FileUtils.compressImage()` 会将图片解码为 Bitmap 后重新压缩为 **JPEG 格式**（硬编码 `Bitmap.CompressFormat.JPEG`），导致：
    - GIF 丢失动画、变为静态 JPG
    - PNG 等格式被强制转为 JPG
    - 分辨率被压缩（默认 `compressionQuality: 30`）
    
    **修复**：所有 `FilePicker` 调用加上 `allowCompression: false`。
    
    之前误判为"MIUI 系统相册自动转格式"（现已删除），实际是 `file_picker` 插件自身行为，AOSP 原生相册即可复现，通过抓取 `FilePickerUtils` 日志 `JPEG_时间戳_.jpg` 可确认来源。

## 测试驱动的渲染诊断

15. **先写测试看输出，再分析，不要上来就猜测** — 遇到 BBCode 渲染类 bug（空白、错位、布局异常），按三层链路逐层 dump 输出，用证据定位：
    - **AST 层**：`BBCodeParser().parse(bbcode)`，用 `JsonEncoder.withIndent('  ')` 打印 `toJson()`，确认解析器对结构的理解
    - **HTML 层**：`BBCode2Html().convert(bbcode)` 直接打印，检查标签结构（如 `<br>` 是否紧贴 `</ul>`）
    - **渲染树层**：widget test 里 `tester.pumpWidget(MaterialApp(home: Scaffold(body: Html(data: html, ...))))`，然后遍历 `find.byType(RichText)` 打印**尺寸 + span 类型 + toPlainText**，看到每个段落的真实排版：
      ```dart
      for (final e in tester.elementList(find.byType(RichText))) {
        final rich = e.widget as RichText;
        final ro = e.renderObject as RenderParagraph?;
        print('${ro?.size}  "${jsonEncode(rich.text.toPlainText())}"');
      }
      ```
      `toPlainText()` 里 `￼`（OBJECT REPLACEMENT CHARACTER）代表 WidgetSpan（图片/内联块），`\n` 代表 `<br>`。**段落末尾的 `\n` 就是空行**。
16. **flutter_html 的 `ImageExtension` 匹配陷阱** — `ImageBuiltIn.matches()` 要求 `src` 带 scheme（`http`/`https`/`data:`/`asset:`）。测试里用相对路径 `src="x.png"` 时扩展**静默不匹配**，builder 不会被调用，图片走默认渲染（表现为找不到自定义组件、无法验证布局）。测试必须用 `https://...` 形式的 src。
17. **`\n → <br>` 与块级边界的通用规则** — `\n → <br>` 是无条件全局替换，BBCode 里换行常出现在块级标签（`[list]`/`[*]`/`[quote]`/`[align]`/`[td]`…）前后，这些 `<br>` 紧贴块级边界会被 flutter_html 渲染成空行（如列表末尾图片下方空白）。**不要逐个补特例正则**（永远有下一个嵌套组合），用一条通用规则替代：*移除与块级标签紧邻（中间仅空白）的 `<br>`，四个方向——开标签前 / 闭标签后 / 闭标签前 / 开标签后*。块级标签集合 `div|blockquote|ul|ol|li|table|tr|td|pre|hr`，未来新增块级标签只需加入集合。注意：[code] 块在清理前已用占位符保护，其内部 `<li><br></li>`（保留行尾换行）不受影响。**占位符盲区**：占位符还原后是块级标签（`[code]` → `<pre>`），但清理时看到的只是 `\x00CODE\d+\x00`——必须把 code 占位符也加入边界标签组，否则 `<br>` 残留在图片与 code 块之间（同样渲染成空行）。
18. **回归测试固定在渲染树层** — 仅断言 HTML 字符串不够（flutter_html 的解析行为是黑盒），用 `testWidgets` 渲染后断言"含图片的段落以图片结尾、无末尾 `\n`"，能直接锁住视觉 bug。同时用参数化用例覆盖多个嵌套组合，防止通用规则回归。
19. **Dart `replaceAll` 不展开 `$1`（JS 陷阱）** — `String.replaceAll(RegExp, '...$1...')` 会把 `$1` 当作**字面量**插入（JavaScript 才会展开）。需要取组时必须用 `String.replaceAllMapped(pattern, (m) => m[1]!)`。排查方法：写个 3 行探针测试确认行为，不要凭记忆写替换串。正则重构时若把 lookbehind + 空串替换改成捕获组，最容易踩此坑（`_brAfterClose`/`_brAfterOpen` 曾因此把字面 `$1` 插进 quote 引文）。

## 通用

20. **CSS 属性提取必须锚定声明起点** — 用正则提取内联样式时，`'color\\s*:\\s*([^;]+)'` 这类**未锚定**的写法会把 `background-color:green` 误判为 `color:green`（`color` 是 `background-color` 的后缀），导致 `<font style="background-color:green">` 被转成 `[background=green][color=green]...[/color][/background]` 多套一层。修复：`(?:^|;)\s*${属性名}\s*:\s*([^;]+)`，锚定到声明起点。

21. **MCP 工具优先** — 新增 API 时先用 Chrome MCP 确认请求/响应格式，再写 Dart 代码。
22. **日志强制 AppLogger** — 严禁 `print`/`debugPrint`，已配置 lint 规则 `no_printf` 阻止。
23. **Controller 绑定优于回调** — 跨 Widget 状态传递用统一的 Controller 实例（如 `BBCodeToolbarController`），比多层回调更易维护。
24. **编辑器页面必须用 PC UA** — 编辑器的 DOM 解析（`PageFetcher.parsePage`）依赖 Discuz PC 版的 HTML 结构（`textarea#e_textarea`, `input#subject`, `a[id^=imageattach]` 等）。之前 `ApiService` 默认使用移动 UA，导致编辑页加载后表单字段为空、图片/附件列表无法识别。修复：`ApiService` 默认请求头改为 `Site.uaPc`，编辑器 `fetchPage` 显式覆写。
25. **`mobile=2` 参数是多余的** — 正确的 UA 比 `mobile=2` 更重要。Discuz 根据 `User-Agent` 头部判断渲染版本，`mobile=2` 仅起辅助作用。移除所有 `&mobile=2` 后，通过 UA 头即可获得正确响应。
26. **Cookie 解析需要异常保护** — Discuz 的部分 Cookie 值包含逗号（如 `discuz_lastvisit=ts1,ts2,ts3`），Dart `dart:io` 的 `Cookie(name, value)` 构造函数严格遵循 RFC 6265，禁止 value 中出现逗号，抛出 `FormatException`。修复：`_parseCookieString` 中 `try/catch` 跳过非法 Cookie。
27. **`package:` 绝对路径优于相对导入** — 2026-07-26 将 `lib/widgets/`（33 文件→6 子目录）和 `lib/core/`（24+6 文件→3 子目录）重组，并统一将全部 `../`/`../../` 相对导入转为 `package:mtbbs/...` 绝对路径。使用绝对路径后，移动文件不需要修改 import 语句。（新增 barrel 文件 `config/config.dart`、`models/models.dart`、`widgets/widgets.dart` + 6 子 barrel、`core/core_parsers/utils/app.dart`。）
